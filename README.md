## 30초 안에 이해하기

AIARC는 **건축 프로젝트에서 문서와 정보가 생성되고, 전달되고, 검토되고, 변경되고, 승인되고, 제출되는 흐름을 자동화하는 AI**를 만듭니다.

출발점은 아주 구체적입니다.

건축사사무소에서 감리·사용승인 실무를 하며, 건설사에서 정리되지 않은 준공 자료를 넘겨받아 다시 찾고, 분류하고, 최신본과 누락을 확인해 제출 가능한 상태로 만드는 일을 반복했습니다.

이 문제를 풀려면 단순한 파일 정리만으로는 부족했습니다.

- 어떤 문서가 서로 연결되는가
- 어떤 파일이 현재 유효한가
- 무엇이 아직 오지 않았는가
- 어떤 자료가 보완 중인가
- 무엇이 승인됐고 무엇이 미결인가
- 최종 제출에 무엇이 반영되어야 하는가

문서는 프로젝트가 진행되는 동안 계속 생성·전달·검토·변경·승인되며 상태가 바뀝니다.

AIARC는 이 **문서 생애주기**를 이해하고 자동화하는 것에서 시작합니다.

> **준공 문서 자동화 → Document Lifecycle AX → 건축 프로젝트 전반의 문서·정보·업무 흐름 AX**

## 문제의 시작: 준공 문서

준공 단계에는 공사기간 동안 쌓인 수많은 자료가 한꺼번에 모입니다.

HWP, PDF, Excel, 사진, 도면, 메일 첨부, 자재·품질·감리·공사 관련 서류가 서로 다른 폴더와 관계자 사이에 흩어져 들어오고, 제출 전에는 다시 정리와 확인이 필요합니다.

실제 업무는 단순 보관이 아닙니다.

```text
자료를 받는다
→ 어느 현장·공종·업무의 문서인지 판단한다
→ 관련 문서와 연결한다
→ 최신 유효본인지 확인한다
→ 누락과 미회신을 확인한다
→ 보완자료를 다시 요청한다
→ 수정·승인본을 반영한다
→ 최종 제출 구조로 정리한다
```

**AIARC는 이 반복적인 준공 문서 업무를 자동화하는 것에서 시작했습니다.**

### 왜 이 문제부터 시작하는가

**실무에서 직접 반복해 본 문제입니다.**  
건설사에서 정리되지 않은 현장 자료를 다시 찾고, 비교하고, 누락과 최신본을 확인해 제출 가능한 상태로 만드는 업무를 직접 경험했습니다.

**법·제도와 연결된 실제 업무입니다.**  
감리, 건축자재 품질관리, 사용승인 과정에는 문서와 도서의 작성·기록·확인·전달·첨부·제출 구조가 존재합니다.

**이미 사람의 시간과 외부 비용이 투입되는 영역입니다.**  
착공·준공서류, 감리 관련 서류, 설계변경 등 건설 문서업무는 실제 외주·대행의 대상이 되고 있습니다. 이것이 AIARC의 구매수요가 검증됐다는 뜻은 아니지만, 비용을 지불해 해결하는 문제라는 시장행동의 신호입니다.

## 파일 정리에서 문서 생애주기로

준공 문서를 자동화하려면 파일을 폴더에 잘 넣는 것만으로는 부족합니다.

같은 문서도 프로젝트가 진행되면서 검토되고, 보완되고, 승인되고, 변경되고, 새로운 버전으로 대체됩니다.

```text
생성
→ 전달
→ 검토
→ 보완
→ 승인
→ 변경
→ 최신 유효본 갱신
→ 최종 제출
```

또한 이 흐름은 폴더 안에서만 일어나지 않습니다.

자재 제조·유통업체, 건설사, CM·건축사사무소 사이에서 자료 요청, 회신, 수정본, 승인과 보완 내용이 이메일과 첨부파일로 계속 오갑니다.

그래서 AIARC의 첫 번째 핵심 능력은 **문서 생애주기를 이해하고 추적하는 것**입니다.

### 1. 문서 관계 연결

HWP, PDF, Excel, 사진, 메일 첨부를 자재·품질·감리·공사·준공 등 관련 업무와 연결합니다.

### 2. 최신 유효본 판별

단순 수정일이 아니라 문서 내용, 버전, 승인·보완·회신 관계를 함께 보고 `유효본 / 구버전 / 확인 필요`를 구분합니다.

### 3. 요청·보완·승인 상태 추적

`요청 → 회신 → 첨부 → 보완 → 수정본 → 승인` 흐름을 연결해 `확보 / 미회신 / 보완 중 / 확인 필요` 상태를 추적합니다.

이 세 가지는 준공 문서에만 필요한 기능이 아닙니다.

자재승인, 품질관리, 검측, 설계변경, 인허가, 감리, 준공처럼 **건축 프로젝트에서 문서와 정보가 오가는 여러 업무에 반복되는 공통 구조**입니다.

## AIARC가 확장하려는 범위

AIARC는 건축사나 현장소장처럼 **건축 전문가의 판단 자체를 대체하려는 제품이 아닙니다.**

대신 건축 전문가들이 프로젝트를 수행하면서 반복적으로 처리하는 문서·정보·업무 흐름을 자동화합니다.

```text
문서와 정보 수집
→ 관계 연결
→ 버전·상태 확인
→ 누락·미회신·보완 추적
→ 필요한 문서·요청 준비
→ 사람 확인이 필요한 예외만 표시
→ 다음 업무 흐름으로 연결
```

첫 제품은 준공 문서 자동화지만, 같은 구조는 프로젝트 전반으로 확장될 수 있습니다.

```text
준공 문서 자동화
↓
Document Lifecycle AX
↓
자재 · 품질 · 감리 · 설계변경 · 인허가 등 인접 workflow
↓
건축 프로젝트 전반의 Document / Information Workflow AX
↓
Architecture Workflow AI
```

> **건축 자체를 AI가 대신하는 것이 아니라, 건축 프로젝트를 움직이는 반복적인 문서·정보·업무 흐름을 AI가 자동화합니다.**

## 현재 제품: 준공 문서 자동화

첫 번째 제품은 **준공 단계의 문서 수집·정리·누락 검토**에서 시작합니다.

```text
현장 폴더 / ZIP
        ↓
      AIARC
        ↓
문서 인식 · 분류 · 관계 연결
        ↓
확보 / 누락 / 확인 필요 / 중복 / 최신본 후보
        ↓
       [전체 정리]
        ↓
정리된 문서 트리 + 검토할 예외만 표시
```

AIARC는 범용 챗봇보다 **자동화가 먼저 일하는 Windows 데스크톱 작업공간**을 지향합니다.

```text
파일 / 폴더 / ZIP 투입
↓
AIARC 자동 분석
↓
정상건 자동 처리
↓
누락 · 충돌 · 애매한 판단만 표시
↓
사람은 필요한 순간에만 확인
```

핵심 제품 원칙은 다음과 같습니다.

**UNDERSTAND → ORGANIZE → CREATE → ACT → TRACK**

- 기존 Windows 폴더·이메일·HWP 중심 업무환경을 존중합니다.
- 정상건은 자동 처리하고 예외만 사람에게 보여줍니다.
- AI 판단은 가능한 한 원문 근거와 연결합니다.
- 법적·기술적 최종판단과 실제 날인·서명은 사람이 유지합니다.

## 어디까지 가는가

AIARC의 확장 방향은 **건축 업무 전체를 하나의 AI가 대신하는 것**이 아닙니다.

준공에서 검증한 문서 생애주기 자동화 구조를 인접 workflow로 넓혀, 자재 제조·유통업체, 건설사, CM·건축사사무소 사이에서 반복되는 문서·정보·업무 흐름을 하나씩 자동화합니다.

장기적으로는 건축 프로젝트 전반에서 다음을 연결하는 **Architecture Workflow AI**를 목표로 합니다.

```text
문서
+ 도면
+ 이메일
+ 승인 / 보완
+ 변경 기록
+ 프로젝트별 업무 흐름
        ↓
      AIARC
        ↓
정리 · 연결 · 추적 · 준비 · 실행 보조
```

설계·법규·기술적 판단과 같은 전문 업무의 최종 권한은 사람에게 남기고, 그 사이에 반복되는 운영·문서·정보 흐름을 점점 더 자동화합니다.
