# AIARC

> **한국 건설사의 Windows PC에서 HWP·메일·현장폴더 위에 올라가, 건설 문서를 이해하고 정리하고 작성하고 추적하여 최종 제출까지 이어주는 local-first 건설 공무 AI 앱.**

AIARC는 새로운 ERP에 모든 자료를 다시 입력하게 하는 제품이 아닙니다. 사용자가 원래 쓰던 **Windows 폴더, 이메일, HWP 중심 문서환경**을 출발점으로 삼고, 그 위에서 문서의 생명주기 자체를 처리하는 것을 목표로 합니다.

## 30초 요약

- **문제**: 건설 문서는 파일 보관으로 끝나지 않습니다. 작성, 증빙 연결, 관계자 전달, 회신, 버전, 누락, 최종 제출까지 계속 상태가 바뀝니다.
- **해결**: AIARC가 메일과 현장폴더를 읽어 문서를 연결하고, 필요한 서류를 준비하며, 누락자료 요청과 회신 상태를 추적해 최종 제출 세트까지 이어줍니다.
- **초기 진입점**: 준공서류 자동정리 + 품질관리서 workflow + 누락자료 요청메일.
- **장기 방향**: 국내 건설 공무 문서 AX → 국내 Architecture Document AX Platform → 장기적으로 국가별 workflow 확장.

## Problem

### 공사가 끝나도 서류는 끝나지 않습니다.

현장에는 공사기간 내내 다음 자료가 이메일과 폴더에 쌓입니다.

- 자재공급원 승인자료
- 품질관리서
- 납품확인서
- 시험성적서와 인증서
- 검측·확인자료
- 공문과 회신본
- 도면, 사진, 보고서
- 준공·사용승인 제출자료

실제 업무는 단순 저장이 아닙니다.

```text
받는다
→ 어느 현장/자재/공종 문서인지 판단한다
→ 관련 증빙과 연결한다
→ 최신본인지 확인한다
→ 필요한 서식을 작성한다
→ 관계자에게 보낸다
→ 회신을 기다린다
→ 수정/날인본을 다시 받는다
→ 빠진 자료를 요청한다
→ 최종 제출 구조로 정리한다
```

즉 건설 문서는 **파일이면서 동시에 업무 상태**입니다.

## Product thesis

AIARC의 핵심은 `파일 정리 AI`나 `건설 챗봇`이 아닙니다.

```text
메일 + 현장 폴더 + 기존 HWP/업무서식
                ↓
              AIARC
                ↓
이해 · 분류 · 관계 연결 · 버전 관리
                ↓
누락/불일치 탐지 · 문서 작성
                ↓
요청 메일 · 회신 추적 · 다음 단계 진행
                ↓
자재승인 / 품질관리 / 검측 / 기성 / 준공·사용승인
```

제품의 다섯 가지 핵심 능력은 **UNDERSTAND → ORGANIZE → CREATE → ACT → TRACK**입니다.

## 왜 한국부터 깊게 파는가

AIARC는 처음부터 범용 글로벌 SaaS를 만들지 않습니다.

> **한국의 HWP와 국내 법정서식이라는 가장 복잡하고 특수한 업무환경부터 깊게 해결합니다.**

한국 건축·건설 실무에는 다음 현실이 한꺼번에 존재합니다.

- HWP 중심 법정·기관·회사 서식
- Windows 중심 사무환경
- 감리·시공·건축주·자재업체 간 이메일 왕복
- 관계자 확인과 날인
- 기관·발주처·현장별 제출체계
- PDF, Excel, 이미지, 도면 등 다양한 파일형식

AIARC는 이 복잡성을 피해서 새 시스템으로 사용자를 옮기는 대신, **기존 업무환경 위에서 작동하는 앱**을 지향합니다.

국내에서 깊이를 먼저 확보하는 이유는 단순한 시장 제한이 아닙니다. 가장 까다로운 로컬 workflow를 실제 제품으로 해결하면서 문서 이해, 관계 연결, 버전·상태 관리, 실행 자동화 역량을 축적하기 위한 전략입니다.

## 첫 번째 Prototype

첫 프로토타입은 전체 건설 공무를 자동화하지 않습니다. 가장 짧게 제품가치를 보여줄 수 있는 세 장면에 집중합니다.

### 1. 준공서류 자동정리

```text
뒤섞인 현장폴더
→ 문서 인식·분류
→ 준공 체크리스트 매칭
→ 확보 / 누락 / 확인 필요 / 중복 표시
→ 번호별 제출폴더 자동생성
→ 관련 파일 분류·복사
```

### 2. 품질관리서 workflow

「건축법 시행령」 제62조에 따른 대상 건축자재 품질관리서는 제조·유통·시공·감리를 거쳐 건축주와 허가권자 제출까지 이어지는 단계적 흐름을 갖습니다.

```text
증빙 연결
→ 품질관리서 작성값 준비
→ 관계자 확인/날인 단계 관리
→ 요청메일
→ 회신 추적
→ 최신본 갱신
→ 다음 단계
→ 최종 제출자료 편입
```

AIARC는 관계자를 대신해 법적 날인이나 전문적 최종판단을 수행하지 않습니다. **작성·연결·전달·추적·누락관리**를 줄이는 것이 역할입니다.

법령 참고: https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1025183813

### 3. 이메일 action

- 누락자료 요청 메일 초안 생성
- 관련 수신자와 첨부자료 추천
- 사용자 확인 후 발송
- 향후 회신 thread 감지와 첨부파일 자동귀속으로 확장

메일은 부가기능이 아니라 **문서 workflow가 다음 단계로 이동하는 transport layer**로 취급합니다.

## AIARC가 선택한 제품 구조

| 구분 | 일반적인 접근 | AIARC |
|---|---|---|
| 시작점 | 새 시스템에 자료 입력·업로드 | 기존 메일·Windows 폴더·HWP |
| 문서 처리 | 저장·검색 또는 개별 문서 AI 기능 | 문서 관계와 workflow 상태 관리 |
| 결과 | 정보 조회·초안 | 다음 행동과 최종 제출물까지 연결 |
| 외부 관계자 | 새 계정/포털 참여가 필요할 수 있음 | 기존 이메일만으로 참여 가능하게 설계 |
| AI 권한 | 자동화 범위가 불명확해질 수 있음 | 근거 표시 + 위험도별 인간 확인 |

AIARC의 목표는 기존 ERP를 통째로 대체하는 것이 아니라, **현재 도구들 사이에서 사람이 직접 기억하고 복붙하고 추적하던 층을 AI 실행 레이어로 바꾸는 것**입니다.

## 왜 지금인가

제품 가설과 별개로, 건설업의 DX·AX 전환 자체는 현재 정책적 문제영역으로도 다뤄지고 있습니다.

2026년 8월 국토교통부와 한국건설기술연구원 스마트건설지원센터는 건설기업의 업무·데이터·시스템 활용현황과 DX·AX 전환 수요를 파악하고 기업별 솔루션 구축·도입 지원방안을 마련하기 위한 수요조사를 실시했습니다. 안내문은 AX 예시로 **AI 기반 문서 작성·검토 및 업무수행 지원**을 포함했습니다.

이 사실은 AIARC의 구매수요나 사업 성공을 증명하는 자료가 아닙니다. 다만 건설기업의 업무 AX가 현재 정책적으로도 탐색되는 영역이라는 timing signal로 봅니다.

참고: https://gyeongnam.kosca.or.kr/bbs/view.do?bbsId=BBS000482&menuId=MENU002987&nttNo=17654

검증 근거와 아직 확인해야 할 가설은 [Evidence & Validation](docs/EVIDENCE_AND_VALIDATION.md)에 분리해 기록합니다.

## Product principles

- **Existing workflow first**: 사용자가 원래 하던 업무를 제품 때문에 다시 하게 만들지 않는다.
- **Local-first**: 원본 파일과 현장 데이터는 가능한 한 사용자 PC/사내 저장소를 중심으로 다룬다.
- **HWP-aware**: HWP를 주변 호환기능이 아니라 국내 건설 실무의 핵심 환경으로 취급한다.
- **Workflow, not chatbot**: 답변보다 실제 다음 업무를 끝내는 데 집중한다.
- **Evidence before automation**: AI 판단과 원문 근거를 연결한다.
- **Human authority remains**: 법적·기술적 최종판단과 실제 날인·서명은 사람이 유지한다.
- **Start narrow, expand by workflow**: 하나의 실제 업무를 끝까지 해결한 뒤 인접 업무로 확장한다.
- **Korea-depth before global breadth**: 국내에서 충분한 제품 깊이를 만든 뒤 장기 확장을 검토한다.

## 20~30년 Roadmap

AIARC는 단기 기능 앱이 아니라 **건축 프로젝트의 문서업무가 장기적으로 어떻게 바뀔지를 보는 사업**을 지향합니다.

```text
준공서류 Prototype
→ 품질관리서 / 자재증빙 Agent
→ Closeout Agent
→ 자재승인 / 검측
→ Construction Document Graph
→ Multi-project / Team
→ Construction Backoffice AX
→ 국내 Architecture Document AX Platform
→ AIARC Core
→ 장기 국가별 Document / Workflow Pack
```

글로벌 확장은 현재 실행 우선순위가 아닙니다. 국내에서 HWP, 법정서식, 현장 문서관계, 이메일 회신, 제출 workflow를 충분히 해결한 뒤에만 검토합니다.

장기 공통 엔진의 핵심은 다음과 같습니다.

```text
수집 → 이해 → 관계 연결 → 생성 → 검토 → 전달 → 회신 추적 → 버전 관리 → 제출
```

자세한 단계와 검증 게이트는 [제품 로드맵](docs/ROADMAP.md)에 기록합니다.

## 현재 단계

**Early prototype / validation stage**

현재 목표는 완성형 제품을 주장하는 것이 아니라, 실제 또는 익명화된 현장자료를 이용해 다음 흐름을 짧고 명확하게 증명하는 것입니다.

```text
폴더 선택
→ 분석
→ 준공 상태 확인
→ 자동 정리
→ 누락자료 확인
→ 요청메일 생성
→ 품질관리서 workflow 확인
```

프로토타입에서 시뮬레이션되는 기능은 시뮬레이션임을 명확히 표시하고, 상용 제품 기능과 혼동시키지 않습니다.
