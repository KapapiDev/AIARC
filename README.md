## 30초 안에 이해하기

건축 프로젝트의 문서는 한 사람이 만들고 끝내는 자료가 아닙니다.

문서 종류에 따라 구체적인 절차는 다르지만, **자재 제조·유통업체, 설계자·건축사사무소, 건설사, 감리자·CM, 건축주, 허가권자 등 여러 주체 사이에서 자료가 작성·전달·확인·보완·제출되는 흐름**이 존재합니다. 일부 품질관리 문서와 감리·사용승인 업무는 이러한 확인·전달·제출 구조가 법령으로도 규정되어 있습니다.

각 단계의 확인 책임은 필요합니다. 문제는 그 사이에서 사람이 반복적으로 수행하는 일입니다.

```text
자료를 받는다
→ 필요한 자료인지 확인한다
→ 누락을 찾는다
→ 보완을 요청한다
→ 수정본을 다시 받는다
→ 최신 유효본을 반영한다
→ 다음 주체에게 전달한다
→ 준공 때 다시 최종 세트를 맞춘다
```

> **AIARC는 법적·기술적 확인 책임을 없애는 것이 아니라, 그 사이의 반복적인 확인·정리·보완·추적 업무를 AX합니다.**

첫 제품은 **준공 문서 자동화**입니다.

## 문제는 “건설사가 서류를 못 정리한다”가 아닙니다

AIARC는 건축사사무소에서 감리·사용승인 실무를 하며 직접 겪은 문제에서 출발했습니다.

준공 단계에서는 건설사로부터 전달받은 자료를 감리자가 확인하고, 설계·변경도서와 최종 시공 상태의 반영 여부를 설계자·건축사사무소가 함께 확인하며, 빠진 자료를 요청하고 수정·보완사항을 반영해 최종 제출 가능한 세트로 완성하는 작업이 반복됩니다.

자료가 잘 정리되어 전달되는 경우도 있습니다. 반대로 거의 정리되지 않은 자료를 다시 분류해야 하는 경우도 있습니다. 하지만 어느 경우든 **사람이 자료의 완성도를 확인하고 부족한 부분을 보완해 다음 단계로 넘기는 작업 자체는 남습니다.**

AIARC가 자동화하려는 것은 바로 이 반복 레이어입니다.

## 왜 하나의 프로젝트 공간인가

기존 방식에서는 각 참여자가 자신의 폴더와 이메일에서 자료를 관리하고 다음 참여자에게 넘깁니다. 전달될 때마다 다시 다운로드하고, 분류하고, 누락을 확인하고, 보완본을 교체하는 작업이 생깁니다.

AIARC가 지향하는 구조는 다릅니다.

```text
프로젝트 생성
→ 프로젝트 코드 발급

자재 제조·유통업체
설계자 · 건축사사무소
건설사
감리자 · CM
등 참여자가 프로젝트에 입장

→ 각자 담당 자료를 직접 업로드
→ AI가 자동 분류·관계 연결
→ 역할별 확인 항목 제시
→ 누락·보완 필요 시 해당 주체에 바로 연결
→ 수정본·확인 결과가 같은 프로젝트에 누적
→ 최신 유효본과 문서 상태를 계속 유지

공사 종료
→ 처음부터 다시 취합하지 않음
→ 누적된 유효 자료에서 준공·사용승인용 제출 세트 생성
```

핵심은 **확인 책임을 AI로 없애는 것**이 아닙니다.

> **법적으로 필요한 확인은 사람이 하고, AIARC는 그 확인이 필요한 자료를 미리 정리하고 상태를 추적해 중복 전달·정리·재확인 단계를 줄입니다.**

---

## 차별점

### 1. 프로젝트 코드로 하나의 문서 흐름

참여자가 같은 프로젝트 공간에 직접 자료를 쌓습니다. 최종 단계에서 여러 폴더와 메일을 다시 합치는 일을 줄입니다.

### 2. AI가 문서 생애주기를 계속 관리

AIARC는 파일을 보관하는 데서 끝나지 않고 다음을 추적합니다.

- 문서 관계 연결
- 최신 유효본 / 구버전 / 확인 필요
- 누락과 미회신
- 요청 → 회신 → 보완 → 수정본 → 확인 상태
- 최종 제출 반영 여부

### 3. 준공 때 다시 만들지 않는다

> **준공서류를 마지막에 정리하는 AI가 아니라, 프로젝트가 진행되는 동안 준공 가능한 문서 상태를 계속 만들어가는 AI.**

공사 중 축적·확인된 유효 자료를 기반으로 최종 제출 패키지를 만듭니다.

## 참여자별 가치

**자재 제조·유통업체**  
담당 자료를 프로젝트에 직접 올리고, 보완 요청과 처리 상태를 확인합니다.

**설계자 / 건축사사무소**  
설계도서와 변경도서를 프로젝트 흐름에 연결하고, 최신 유효본과 변경 반영 상태를 확인하며 시공·감리 단계에서 필요한 보완과 최종도서 정리를 추적합니다.

**건설사**  
업체별 자료를 받아 다시 폴더를 만드는 일을 줄이고, 무엇이 확보·누락·보완 중인지 확인합니다.

**감리자 / CM**  
전달받은 자료를 처음부터 다시 정리하기보다, 확인이 필요한 항목과 근거 중심으로 검토하고 보완·회신 상태를 추적합니다.

**건축주·최종 제출 단계**  
프로젝트 진행 중 누적된 유효 자료에서 제출 준비 상태와 최종 세트를 확인합니다.

문서마다 동일한 참여자 순서와 확인 절차를 갖는 것은 아닙니다. AIARC는 문서·업무별 실제 workflow와 책임을 구분해 적용하는 것을 전제로 합니다.

## 현재 제품: 준공 문서 자동화

현재 AIARC 0.6.0은 준공 단계의 제품 경험을 보여주는 프로토타입입니다.

```text
현장 폴더 / ZIP
→ 문서 인식·분류
→ 관계 연결
→ 확보 / 누락 / 확인 필요 / 중복 / 최신본 후보
→ 전체 정리
→ 원문 근거 확인
```

현재 데모는 준비된 샘플 자료를 사용합니다. AI 분석과 메일 가져오기 등 시뮬레이션되는 기능은 실제 구현 범위와 구분해 공개합니다.

다음 실제 검증에서는 현장자료를 이용해 문서 분류, 관계 연결, 최신본 후보, 누락·불일치 탐지와 수작업 시간 감소를 측정합니다.

## 확장 방향

AIARC의 확장은 `준공 프로그램 → 건축 자체를 수행하는 AI`가 아닙니다.

준공에서 검증한 구조를 같은 문서 흐름의 앞단과 인접 업무로 넓힙니다.

```text
준공 문서 자동화
↓
Document Lifecycle AX
↓
설계 · 인허가 · 자재 · 품질 · 감리 · 설계변경 등 문서 workflow
↓
건축 프로젝트 전반의 Document / Information Workflow AX
↓
Architecture Workflow AI
```

> **건축 전문가를 대체하는 것이 아니라, 건축 프로젝트에서 여러 참여자가 반복하는 문서·정보·업무 흐름을 자동화합니다.**

## 제품 원칙

- **Workflow first**: 파일 저장보다 실제 전달·확인·보완·제출 흐름을 먼저 봅니다.
- **Automation first**: 정상건은 자동 처리하고 예외와 확인 필요 항목만 사람에게 보여줍니다.
- **Evidence before automation**: AI 판단은 가능한 한 원문 근거와 연결합니다.
- **Human authority remains**: 법적·기술적 판단, 확인, 서명·날인의 권한은 사람에게 남깁니다.
- **HWP-aware**: HWP/HWPX를 국내 건축·건설 실무의 핵심 형식으로 봅니다.
- **No universal checklist fiction**: 문서마다 적용 법령·프로젝트 조건·참여자·필요 서류가 다를 수 있음을 전제로 합니다.
