## 30초 안에 이해하기

AIARC는 **자재 제조·유통업체, 설계자·건축사사무소, 건설사, 감리자·CM**이 주고받은 문서·도면·메일·변경 흔적을 연결해 프로젝트의 현재 상태를 재구성하고, 다음 업무까지 이어가는 AI입니다.

건축 프로젝트의 현재 상태는 한곳에 기록되어 있지 않습니다.

도면, HWP, PDF, Excel, 이메일, 사진, BIM, 승인 기록과 변경본이 흩어져 있고, 사람은 이를 직접 찾아 비교하고 정리해 왔습니다.

- 이 자료가 어느 현장·공종·업무와 연결되는가
- 어떤 파일이 최신 유효본인가
- 무엇이 승인됐고 무엇이 아직 미결인가
- 변경사항이 최종 결과에 반영됐는가
- 무엇이 빠졌고 다음에 무엇을 해야 하는가

**AIARC는 건축사사무소에서 건축사보로 근무하며 감리·사용승인 실무에서 직접 겪은 문제에서 출발했습니다.**

준공 단계에서 건설사로부터 전달된 자료를 확인하고, 빠진 자료를 요청하고, 수정·보완본과 최신본을 반영해 제출 가능한 상태로 완성하는 일을 반복해 왔습니다. 자료가 잘 정리되어 오는 경우도 있지만, 때로는 거의 정리되지 않은 자료를 다시 분류해야 하는 경우도 있었습니다.

AIARC는 특정 직무의 문서 작성·검색을 돕는 AI가 아닙니다. **프로젝트 참여자 사이에 흩어진 정보를 연결해 지금 프로젝트가 어떤 상태인지 이해하고, 그 상태를 바탕으로 다음 업무까지 이어가는 AI**를 지향합니다.

> **AIARC가 관리하는 기본 단위는 파일이나 한 사람의 업무가 아니라 프로젝트의 현재 상태입니다.**

```text
문서 · 도면 · 메일 · 사진 · BIM · 변경 기록
                    ↓
         Project State Reconstruction
                    ↓
       현재 상태 · 관계 · 미결사항
                    ↓
          Next-action reasoning
                    ↓
             업무 실행
                    ↓
          프로젝트 상태 갱신
```

> **AIARC = 프로젝트의 현재 상태를 재구성하고, 그 상태를 바탕으로 다음 업무를 수행하는 AI**

## 첫 번째 진입점: 준공 문서 자동화

AIARC는 이 큰 문제를 한 번에 풀지 않습니다.

첫 번째 제품은 **준공 단계의 문서 수집·정리·누락 검토**에서 시작합니다. 이를 통해 흩어진 자료에서 제출 준비 상태를 파악하는 구조를 검증합니다.

```text
현장 폴더 / ZIP
        ↓
      AIARC
        ↓
문서 인식 · 분류 · 관계 연결
        ↓
확보 / 누락 / 확인 필요 / 중복 / 최신본 후보
        ↓
       [전체 정리]
        ↓
정리된 문서 트리 + 검토할 예외만 표시
```

### 왜 이 문제부터 시작하는가

**첫째, 실제 실무에서 반복되는 문제입니다.**

준공 단계에서는 전달받은 자료를 확인하고, 누락된 자료를 요청하고, 수정·보완본과 최신본을 반영해 제출 가능한 상태로 완성하는 작업이 반복됩니다. 자료의 정리 상태는 프로젝트마다 다르지만, 사람이 완성도를 확인하고 부족한 부분을 보완하는 업무는 남습니다.

**둘째, 법·제도적으로도 존재하는 업무 흐름입니다.**

현행 「건축법」과 하위법령에는 감리, 건축자재 품질관리, 사용승인 과정에서 문서와 도서의 **작성·기록·확인·전달·첨부·제출** 구조가 존재합니다. 즉 이 문제는 개인의 파일정리 습관이 아니라 **프로젝트의 확인·책임·사용승인과 연결된 구조적 업무**입니다.

**셋째, 이미 비용이 지출되는 문제입니다.**

착공·준공서류, 감리 관련 서류, 설계변경 등 건설 공무 문서업무는 이미 외주·대행 서비스의 대상이 되고 있습니다. 이것이 AIARC 자체의 구매수요가 검증됐다는 의미는 아니지만, **사람의 시간과 외부 비용을 지불해서라도 해결되는 문제라는 시장행동의 신호**입니다.

**넷째, AIARC의 핵심 가설을 작게 검증하기 좋은 지점입니다.**

준공 단계에는 프로젝트 전 과정에서 생성된 결과물이 모이고, 누락·최신본·관계·변경 반영 여부를 함께 판단해야 합니다. 그래서 준공 문서는 최종 목적지가 아니라 **Project State Reconstruction을 가장 작고 검증 가능하게 시작하는 첫 관측 지점**입니다.

## 준공 때 모으는 대신, 공사 중 함께 완성합니다

현재 0.6.0 프로토타입은 **준공 단계에 이미 흩어져 있는 자료를 AI가 정리하는 경험**부터 보여줍니다.

하지만 AIARC가 제안하는 다음 업무 방식은 사후 정리에서 한 단계 더 나아갑니다.

```text
프로젝트 생성
→ 프로젝트 코드 / 초대 링크 발급

자재 제조·유통업체
건설사
감리자 · CM
필요한 경우 설계자 · 건축사사무소
        ↓
같은 프로젝트에 담당 자료를 직접 추가
        ↓
AIARC가 자동 분류 · 관계 연결 · 버전 관리
        ↓
누락 · 보완 · 최신 유효본 · 확인 필요 상태를 계속 갱신
        ↓
각 참여자는 자신이 확인해야 할 항목 중심으로 검토
        ↓
수정본과 보완 결과가 같은 프로젝트에 누적
        ↓
공사 완료
        ↓
누적된 유효 자료에서 준공 · 사용승인용 최종 세트 생성
```

사람이 확인해야 할 건 사람이 확인합니다. AIARC는 그 과정에서 반복되는 **정리·누락 확인·보완 요청·수정본 반영·전달·추적** 업무를 줄입니다.

> **건물을 짓는 동안, 준공서류도 함께 완성됩니다.**

### 이 구조의 차별점

**1. 하나의 프로젝트에 자료가 바로 쌓입니다.**  
마지막 단계에서 여러 회사의 폴더와 메일을 처음부터 다시 합치는 일을 줄입니다.

**2. AI가 문서의 생애주기를 계속 관리합니다.**  
단순 저장이 아니라 관계, 최신 유효본, 누락, 보완, 확인 상태와 최종 제출 반영 여부를 이어서 추적합니다.

**3. 준공 때 다시 만드는 일을 줄입니다.**  
공사 중에 생성·확인·보완된 유효 자료가 계속 누적되기 때문에 공사 종료 시점에는 최종 제출 세트가 이미 상당 부분 완성된 상태를 목표로 합니다.

프로젝트 코드 자체가 차별점의 전부는 아닙니다. 핵심은 **여러 참여자가 같은 프로젝트에서 자료를 만들고 확인하는 동안 AI가 문서 상태를 계속 관리해, 준공 직전의 재취합과 재정리를 구조적으로 줄이는 것**입니다.

## 프로젝트 상태는 파일만으로 알 수 없습니다

건축 프로젝트의 현재 상태는 하나의 파일이나 폴더에 완성된 형태로 기록되지 않습니다.

같은 문서와 도면도 프로젝트가 진행되면서 검토되고, 승인되고, 변경되고, 새로운 버전으로 대체됩니다.

```text
생성
→ 검토
→ 승인
→ 현장 반영
→ 변경
→ 재검토 / 재승인
→ 최신 유효본 갱신
→ 준공 반영
→ 최종 제출
```

따라서 같은 도면번호나 같은 문서명이 여러 개 있다고 해서 `최근 수정일 = 현재 유효본`이라고 단순하게 판단할 수 없습니다.

또한 프로젝트 정보는 폴더 안에만 존재하지 않습니다. 자재 제조·유통업체, 설계자·건축사사무소, 건설사, 감리자·CM 사이에서 **자료 요청, 보완 요청, 회신, 수정본, 승인과 변경 내용이 이메일과 첨부파일로 계속 오갑니다.**

AIARC는 이러한 문서·도면·메일·변경 흔적을 서로 연결해,

- 지금 어떤 자료가 유효한지
- 무엇이 승인되었는지
- 무엇이 아직 미결인지
- 어떤 변경이 최종 결과에 반영됐는지
- 무엇이 빠졌고 다음에 무엇을 해야 하는지

를 이해하는 방향으로 발전합니다.

> **문서를 정리하는 것이 목적이 아니라, 흩어진 흔적에서 프로젝트의 현재 상태를 재구성하는 것이 목적입니다.**

## 제품 경험

AIARC는 범용 챗봇이 아니라, **자동화가 먼저 일하는 Windows 데스크톱 작업공간**을 지향합니다.

```text
파일 / 폴더 / ZIP 투입
↓
AIARC 자동 분석
↓
정상건 자동 처리
↓
누락 · 충돌 · 애매한 판단만 표시
↓
사람은 필요한 순간에만 확인
```

핵심 원칙은 단순합니다.

**UNDERSTAND → ORGANIZE → CREATE → ACT → TRACK**

- 기존의 Windows 폴더·이메일·HWP 중심 업무환경을 존중합니다.
- 정상건은 자동 처리하고 예외만 사람에게 보여줍니다.
- AI 판단은 가능한 한 원문 근거와 연결합니다.
- 법적·기술적 최종판단과 실제 날인·서명은 사람이 유지합니다.

## 현재 단계

**Stage: Prototype / validation**

현재 AIARC는 핵심 제품 경험과 업무 흐름을 검증하는 프로토타입 단계입니다.

현 단계에서는 실제 제품으로 이어질 UI/UX와 핵심 업무 흐름을 먼저 시연하고, 이후 실제 현장자료를 이용해 문서 분류, 최신본 후보, 누락·불일치 탐지와 업무시간 절감 효과를 검증합니다.

프로토타입에서 시뮬레이션되는 기능은 실제 구현 범위와 구분해 공개합니다.

> **프로젝트의 실제 상태를 스스로 재구성하고, 그 상태를 바탕으로 다음 업무를 수행한다.**
