# AIARC

> 건설 서류가 만들어지고, 전달되고, 확인되고, 회신되고, 최종 제출될 때까지의 흐름을 AI가 함께 처리하는 건설 공무 AI 에이전트.

AIARC는 건설회사가 이미 사용하는 **Windows 폴더, 이메일, HWP 중심 문서환경** 위에서 동작하는 것을 목표로 합니다. 새로운 ERP에 모든 자료를 다시 입력하게 하기보다, 기존 업무 흐름을 읽고 필요한 문서를 정리·생성·추적하여 최종 제출물까지 이어주는 `local-first` 건설 Document / Backoffice AX 제품입니다.

## Problem

건설 공무의 문서는 단순한 파일 보관물이 아닙니다.

현장에서는 다음과 같은 일이 반복됩니다.

- 이메일로 납품확인서, 시험성적서, 인증서, 승인자료 등을 수신한다.
- 파일을 현장·공종·자재별로 분류하고 이름과 최신본을 관리한다.
- 회사가 직접 작성해야 하는 HWP 법정·업무 서식을 반복 작성한다.
- 제조업자, 유통업자, 시공자, 감리자, 건축주 등 여러 관계자 사이에서 확인·날인본을 주고받는다.
- 회신 여부와 최신 날인본을 추적한다.
- 준공·사용승인 시점에 필요한 증빙을 다시 대조하고 누락자료를 요청한다.
- 최종 제출 폴더와 문서 세트를 수작업으로 만든다.

특히 「건축법 시행령」 제62조의 품질관리서처럼 제조업자 → 유통업자 → 공사시공자 → 공사감리자 → 건축주/허가권자로 이어지는 법정 제출 흐름이 존재하는 영역에서는 **문서의 존재뿐 아니라 일치 여부, 전달 단계, 최종본 관리가 중요**합니다.

## Product thesis

AIARC의 핵심은 `파일 정리 AI`가 아닙니다.

```text
메일 + 현장 폴더 + 기존 서식
          ↓
        AIARC
          ↓
이해 · 분류 · 관계 연결 · 버전 관리
          ↓
누락/불일치 탐지 · 문서 작성
          ↓
요청 메일 · 회신 추적 · 다음 단계 진행
          ↓
자재승인 / 품질관리 / 기성 / 준공 제출물
```

즉 AIARC는 **정리 + 생성 + 실행 + 추적 + 제출**을 하나의 문서 생명주기로 연결하는 것을 목표로 합니다.

## Korea-first strategy

AIARC는 처음부터 범용 글로벌 SaaS를 만들지 않습니다.

> **한국의 HWP와 국내 법정서식이라는 가장 복잡하고 특수한 업무환경부터 깊게 해결합니다.**

한국 건축·건설 실무에는 HWP 법정서식, Windows 중심 사무환경, 감리·시공·건축주·자재업체 간 이메일 회신, 기관과 발주처별 제출체계가 결합되어 있습니다. AIARC는 이 현실을 피하지 않고 제품의 출발점으로 삼습니다.

초기 목표는 `한국용 기능 몇 개`가 아니라 **한국 건설 문서 workflow를 실제로 끝내는 깊이**를 확보하는 것입니다. 이후 같은 엔진을 자재승인, 검측, 기성, 설계변경, 준공·사용승인 등으로 확장합니다.

## First prototype

첫 프로토타입은 전체 건설 공무를 자동화하지 않습니다. 모두의 창업 및 후속 창업지원 검증을 위해 가장 이해하기 쉬운 범위부터 시작합니다.

### 1. 준공서류 자동 정리

현장 폴더를 선택하면:

1. 파일을 읽고 문서 종류를 판별한다.
2. 준공 체크리스트와 비교한다.
3. `확보 / 누락 / 확인 필요 / 중복` 상태를 보여준다.
4. 번호가 붙은 제출용 폴더 구조를 만든다.
5. 관련 파일을 자동 분류·복사한다.

### 2. 품질관리서 workflow proof

품질관리서 업무를 첫 번째 깊은 AX workflow 후보로 둡니다.

```text
관련 증빙 수집
→ 품질관리서 작성 데이터 구성
→ 법정 서식 작성
→ 관계자 확인/날인 요청
→ 이메일 회신 추적
→ 최신본 반영
→ 다음 관계자 전달
→ 최종본 확정
→ 준공/사용승인 자료에 편입
```

실제 HWP 자동작성은 프로토타입 일정과 기술 검증 결과에 따라 범위를 조절할 수 있습니다. **HWP는 상용 제품에서 중요한 핵심 통합 대상이지만, 프로토타입 제출을 막는 선행조건으로 두지 않습니다.**

### 3. 이메일 action

초기에는 완전자율 발송보다 안전하고 검증하기 쉬운 흐름부터 시작합니다.

- 누락자료 요청 메일 초안 생성
- 관련 수신자/자료 추천
- 사용자가 확인 후 발송
- 이후 버전에서 회신 자동감지, 재요청, 단계 전환으로 확장

## Product principles

- **Existing workflow first**: 새 시스템에 자료를 다시 올리게 만들지 않는다.
- **Local-first**: 원본 파일과 현장 데이터는 가능한 한 사용자 PC/사내 저장소를 중심으로 다룬다.
- **HWP-aware**: 한국 건설 실무의 HWP 중심 작성환경을 제품의 핵심 현실로 취급한다.
- **Korea-depth before global breadth**: 국내 법정서식과 실제 업무흐름을 먼저 깊게 해결한 뒤 확장한다.
- **Evidence before automation**: AI가 추정한 내용과 원문 근거를 구분한다.
- **Human authority remains**: 날인, 법적 판단, 기술적 최종판단을 AI가 임의로 대체하지 않는다.
- **Workflow, not chatbot**: 질문에 답하는 것보다 실제 다음 업무를 끝내는 데 초점을 둔다.
- **Start narrow, expand by workflow**: 하나의 실제 업무를 끝까지 자동화한 뒤 인접 업무로 확장한다.

## Long-term direction

AIARC는 단기 기능 앱이 아니라 **20~30년 관점에서 건축 프로젝트의 문서 업무가 어떻게 바뀔지를 보는 장기 사업**을 지향합니다.

```text
준공 폴더 정리
        ↓
품질관리서 / 자재서류 workflow
        ↓
메일 + HWP + 현장폴더 통합
        ↓
자재승인 / 검측 / 기성 / 설계변경 / 준공
        ↓
Construction Document Graph
        ↓
건설 공무 AI Agent
        ↓
국내 Architecture Document AX Platform
        ↓
AIARC Core 분리
        ↓
국가별 Document / Workflow Pack
        ↓
Global Architecture Document AX Platform
```

장기적으로 AIARC는 문서를 보관하는 시스템이 아니라, **현장의 문서 관계와 업무 상태를 이해하고 다음 행동을 수행하는 건축 문서 실행 레이어**를 목표로 합니다.

글로벌 확장은 현재의 실행 우선순위가 아닙니다. 국내에서 HWP, 법정서식, 현장 문서관계, 이메일 회신, 제출 workflow를 충분히 깊게 해결한 뒤 장기적으로 검토합니다.

장기적인 공통 엔진은 다음 문서 생명주기를 담당합니다.

```text
수집
→ 이해
→ 관계 연결
→ 생성
→ 검토
→ 전달
→ 회신 추적
→ 버전 관리
→ 제출
```

국가가 바뀌면 법규, 서식, 언어, 역할구조와 업무관행은 달라질 수 있지만 이 핵심 엔진 위에 국가별 `Document / Workflow Pack`을 얹는 확장 가능성을 열어둡니다.
