# AIARC Product Roadmap

Updated: 2026-09-04

## 0. 로드맵 원칙

AIARC의 로드맵은 기능 목록이 아니라 **20~30년 관점의 사업 방향과 단계별 검증 계획**입니다.

핵심 전략은 두 문장으로 정리합니다.

> **HWP와 국내 법정서식처럼 복잡하고 특수한 한국의 업무환경부터 깊게 해결한다.**

> **글로벌은 지금의 실행목표가 아니라, 국내에서 충분한 제품 깊이와 업무 자산을 만든 뒤 검토하는 장기 옵션이다.**

개발은 항상 작게 시작합니다.

```text
설명 가능한 데모
→ 실제 현장자료에서 작동
→ 하나의 업무 흐름을 끝까지 해결
→ 반복사용
→ 인접 업무 확장
→ 여러 현장·조직
→ 국내 건설 Document AX
→ Architecture Document AX Platform
```

고정된 연도 약속보다 **검증 게이트**를 우선합니다. 이전 단계의 핵심 가설이 확인되지 않으면 다음 단계의 규모를 키우지 않습니다.

# Phase 0. 모두의 창업 Prototype

## 목적

**건설 공무 문서업무의 일부를 AIARC가 실제로 줄일 수 있다는 점을 짧고 명확하게 보여줍니다.**

제품 전체를 완성하려 하지 않습니다. `Before → AIARC → After`가 분명해야 합니다.

## 핵심 데모

```text
뒤섞인 현장 준공폴더
        ↓
      AIARC
        ↓
문서 인식·분류
        ↓
확보 / 누락 / 확인 필요 / 중복
        ↓
번호별 준공폴더 자동정리
        ↓
품질관리서 업무 흐름
        ↓
누락자료 요청메일
```

## 반드시 보여줄 것

- Windows desktop 중심 UI
- 현장 폴더 선택
- 파일목록·메타데이터 읽기
- 문서 분류 결과 표시
- 준공항목 매칭
- 확보·누락·확인 필요·중복 표시
- 제출용 번호 폴더 생성 시연
- 파일 분류·복사 시연
- 품질관리서 업무 흐름 화면
- 요청메일 생성
- 최소 1개 문서생성 결과 표시

## 가능하면 포함할 것

1. Gmail 또는 Outlook draft 생성
2. 중복·최신본 후보 판별
3. 현장정보 자동추출
4. HWP 품질관리서 템플릿 1종 자동작성
5. 회신 첨부파일 자동분류

## 프로토타입을 막아서는 안 되는 항목

다음은 중요하지만 Phase 0의 선행조건으로 두지 않습니다.

- 모든 HWP 서식 자동화
- 완전자율 이메일 발송
- 실시간 회신 추적 완성
- 모든 메일 서비스 지원
- 모든 ERP 연동
- 다중회사 권한체계
- 자체 LLM
- 온프레미스 AI

HWP 우선순위:

```text
1. 실제 HWP 자동작성 1종
2. 제한 템플릿 자동채움
3. 생성값 preview + 수동반영
```

## 데모 정직성

시뮬레이션되는 기능은 `Prototype Demo` 또는 `Demo Mode`로 표시합니다.

```text
Desktop UI
↓
Agent Interface
├─ DemoEngine
└─ RealAIEngine
```

1차에서 DemoEngine을 사용하더라도 이후 RealAIEngine으로 교체할 수 있는 구조를 유지합니다.

## 완료 기준

```text
폴더 선택
→ 분석
→ 준공상태 확인
→ 자동정리
→ 누락항목 확인
→ 요청메일 생성
→ 품질관리서 업무 흐름 확인
```

제품을 처음 보는 사람이 1분 안에 다음을 이해해야 합니다.

> `건설현장의 메일과 파일을 읽고, 정리하고, 작성하고, 다음 업무까지 이어주는 Windows AI 앱이구나.`

# Phase 0.5. Validation

## 목적

보기 좋은 데모에서 멈추지 않고 **실제 현장 문제와 제품가설을 검증**합니다.

## 실무 검증 질문

- 실제로 시간이 많이 드는 문서업무는 무엇인가
- 준공 누락체크가 유용한가
- 분류 오류는 어느 정도까지 허용 가능한가
- 품질관리서 업무 흐름이 실제 업무와 맞는가
- HWP 자동작성은 어느 수준부터 가치가 생기는가
- 메일 자동화는 어디까지 맡길 수 있는가
- 설치형 Windows 앱에 대한 거부감은 있는가
- 어떤 가격방식이 자연스러운가

## 자료 검증

가능하면 서로 다른 2~3개 현장 자료에서 테스트합니다.

한 현장의 폴더명·파일명 규칙에 과적합하지 않도록 합니다.

## 다음 단계로 넘어가는 기준

- 실무자가 문제를 명확히 인정한다
- 실제 자료에서 의미 있는 분류가 가능하다
- 누락·상태 표시가 실제 업무에 도움이 된다
- 반복 사용 의향을 확인한다
- 다음 자동화 업무가 구체적으로 도출된다

# Phase 1. Usable Alpha

## 목표

`시연 앱`에서 **한 현장에서 계속 켜두고 쓸 수 있는 프로그램**으로 이동합니다.

초기 사용자는 한 번에 현장 1~3개를 관리하는 공무 담당자를 상정합니다.

## 기능

### Persistent Project

- 현장 마스터
- 관계자
- 문서 인덱스
- 업무 상태
- 사용자 수정 이력

### Folder Watcher

```text
새 파일
→ 분류
→ 기존 문서와 연결
→ 사용자 확인
→ 현장상태 갱신
```

### Email Integration v1

- 현장 관련 메일 검색
- 첨부 다운로드
- 문서 자동귀속
- 요청메일 draft 생성

### HWP v1

가치가 높은 HWP 서식 1~3종부터 지원합니다.

1순위 후보는 품질관리서입니다.

### Evidence UI

AI 판단의 근거 파일과 추출값을 보여줍니다.

### Safe Recovery

잘못된 분류나 이동을 되돌릴 수 있어야 합니다.

## 다음 단계로 넘어가는 기준

- 실사용자 3~5명 수준의 초기 검증
- 실제 현장에서 반복사용
- 가장 많이 수정되는 AI 판정 데이터 확보
- 작업시간 절감 측정 시작
- 다음 업무의 우선순위 확정

# Phase 2. Quality Document Agent

## 목표

품질관리서와 자재 증빙관리 업무를 **첫 번째 완성형 Agent Loop**로 만듭니다.

```text
자재자료 수신
→ 현장·자재 귀속
→ 납품확인서 / 시험성적서 / 인증자료 연결
→ 품질관리서 작성
→ 관계자 확인상태 관리
→ 다음 관계자 요청메일
→ 회신 감지
→ 최신본 판별
→ 다음 단계
→ 최종본
→ 준공자료 편입
```

## 핵심 기능

- Material Record
- 제조사·제품명·규격·번호·날짜 간 문서 대조
- Workflow Engine
- Reply Tracking
- Version Graph
- 근거·감사 로그

최종 적합성 판단과 법적 책임은 사람이 유지합니다.

## 다음 단계로 넘어가는 기준

- 품질관리서 단위의 상태를 한 화면에서 신뢰성 있게 관리
- 요청→회신→다음 단계가 실제 업무에서 작동
- HWP 연동 깊이의 실사용 가치 확인
- 업무시간 절감 또는 누락 감소 정량화 시작

# Phase 3. Closeout Agent

## 목표

준공 직전에 자료를 모으는 제품이 아니라 **공사 중부터 준공 가능한 상태를 유지하는 Agent**로 발전합니다.

## 기능

- Dynamic Closeout Checklist
- 현장별 요구항목 설정·학습
- Continuous Readiness
- 누락자료 탐지
- 보유 가능성이 높은 관계자 추천
- 요청메일→회신→자동편입
- 번호별 제출 폴더
- INDEX·제출목록
- 누락·해당없음 기록
- 최종 package 생성

## 다음 단계로 넘어가는 기준

- 준공 직전 수작업을 실제로 줄였다는 사례 확보
- 누락을 더 일찍 발견한 사례 확보
- 공사 중 지속 사용 가치 확인

# Phase 4. Material Approval + Inspection

## 목표

AIARC를 `준공 때 쓰는 프로그램`에서 **매일 쓰는 공무도구**로 확장합니다.

### 자재승인

```text
자재 선택
→ 업체자료 수집
→ 시험성적서·인증서·카탈로그 연결
→ 승인 package 구성
→ 감리 요청
→ 보완 회신
→ Revision 관리
→ 승인본 확정
```

### 검측·검수

- 관련 도면·사진·자재자료 연결
- 기존 양식 작성 보조
- 제출·회신 상태관리

## 다음 단계로 넘어가는 기준

- 일상적인 반복사용 빈도 상승
- 준공 이전 단계에서도 지속 가치 확인
- 인접 업무 사이의 동일 데이터 재사용 확인

# Phase 5. Construction Document Graph

## 목표

파일 중심 앱에서 **현장 문서관계를 이해하는 시스템**으로 발전합니다.

```text
Project
├─ Parties
├─ Contracts
├─ Materials
├─ Work items
├─ Documents
├─ Email threads
├─ Revisions
├─ Approvals
└─ Workflows
```

## 가능해지는 기능

- 최신 승인본 찾기
- 회신 없는 문서 찾기
- 준공 누락자료 찾기
- 서로 다른 문서의 제품·규격 불일치 후보 탐지
- 설계변경 이후 영향을 받는 문서 연결

Document Graph는 단순 저장 DB가 아니라 **다음 행동을 결정하기 위한 맥락 정보의 기반**입니다.

# Phase 8. Domestic Architecture Document AX Platform

## 목표

시공사 공무문서에서 출발한 AIARC를 **국내 건축 프로젝트 전체의 문서 생명주기를 다루는 실행 플랫폼**으로 확장합니다.

대상 역할:

```text
건축주 / 시행사
설계사 / 건축사사무소
감리 / CM / PM
시공사
전문건설사
자재 제조·유통사
```

대상 문서와 업무:

```text
설계도서
공문
계약문서
자재승인
품질관리
검측
기성
설계변경
준공
사용승인
유지관리 인계문서
```

공통 엔진:

```text
Document Intelligence
+
Project Document Graph
+
Workflow Engine
+
HWP / Office Actions
+
Email Agent
+
Evidence / Audit Layer
```

장기 국내 목표는 **한국 건축·건설 문서업무의 표준 AI 실행 레이어**가 되는 것입니다.

# Phase 9. AIARC Core

## 목표

국내에서 오랫동안 검증한 기능을 특정 서식 하나에 종속되지 않는 공통 엔진으로 정리합니다.

```text
수집
→ 이해
→ 관계 연결
→ 생성
→ 검토
→ 전달
→ 회신 추적
→ 버전 관리
→ 제출
```

Core 분리는 국내 제품을 범용화해 얕게 만들기 위한 것이 아닙니다.

**국내 제품은 계속 HWP와 국내 법정서식을 가장 깊게 지원합니다.** Core는 장기 아키텍처의 분리입니다.

# Phase 10. Long-term Global Option

## 성격

**20~30년 장기 옵션이며 현재의 실행 우선순위가 아닙니다.**

해외 진출은 한국 제품을 번역하는 문제로 보지 않습니다.

국가가 바뀌면 다음 항목을 다시 검증해야 합니다.

- 현지 법규와 법정서식
- 건축주·설계·감리·시공 역할구조
- 제출·승인 절차
- Windows·Mac 및 Office 환경
- 이메일·협업도구
- 현지 문서 샘플
- 서명·전자서명·날인 문화
- 데이터 보호·보존 규정

확장을 결정한다면 국가별 `Document / Workflow Pack`을 별도로 구축합니다.

```text
AIARC Core
├─ Korea Pack
│  ├─ HWP
│  ├─ 국내 법정서식
│  ├─ 감리·시공 workflow
│  └─ 준공·사용승인 체계
│
└─ Future Country Pack
   ├─ 현지 문서 포맷
   ├─ 현지 법규·서식
   └─ 현지 workflow
```

이 단계가 필요한지 자체도 미래에 시장과 제품이 충분히 증명한 뒤 판단합니다.

## 장기 North Star

> **건축 프로젝트에서 문서가 만들어지고, 전달되고, 검토되고, 수정되고, 승인되고, 최종 제출될 때까지 AIARC가 그 생명주기를 이해하고 실행하는 Architecture Document AX Platform**

중요한 것은 `글로벌`이라는 단어가 아니라 **국내에서 시작한 하나의 실제 업무 흐름이 20~30년에 걸쳐 어떤 공통 실행 엔진으로 발전하는가**입니다.

---

## 하지 않을 것

- 데모 전에 자체 AI 모델부터 만들기
- ERP 전체를 먼저 만들기
- 모든 법정서식을 한 번에 지원하기
- HWP 기술문제 하나 때문에 전체 프로토타입을 중단하기
- 사용자가 원하지 않은 현장관리 기능까지 무작정 확장하기
- AI가 법적·기술적 책임을 대신하는 것처럼 표현하기
- 실사용 검증 전에 완전자율성을 과도하게 높이기
- 실제 현장자료를 공개 저장소에 넣기
- 국내 업무 깊이를 만들기 전에 글로벌 제품부터 설계하기
- 로드맵의 큰 비전을 현재 구현된 기능처럼 표현하기

다음 Phase를 선택할 때는 항상 이 질문으로 돌아갑니다.

> **지금 실제 사용자가 반복하는 업무 중, AIARC가 가장 안전하고 검증 가능하게 더 많이 끝낼 수 있는 다음 한 단계는 무엇인가?**
