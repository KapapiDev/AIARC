# AIARC Public Roadmap

## North Star

> **AIARC의 최종 목표는 건축 프로젝트에 필요한 지식업무 전반을 수행하는 건축 특화 AI, `Architecture AI`를 만드는 것입니다.**

준공 문서 자동화는 최종 목적지가 아니라, 건축 AI가 실제 프로젝트를 이해하고 업무를 수행하기 위한 첫 번째 진입점입니다.

```text
준공 문서 자동화
        ↓
건설 문서 Lifecycle AI
        ↓
Project Intelligence
        ↓
Architecture / Construction Agent
        ↓
Architecture AI
```

AIARC는 큰 비전을 한 번에 구현하지 않습니다. 실제 현장자료와 사용자 검증을 통과한 범위부터 넓혀갑니다.

---

## Phase 0 — Prototype

현재 단계입니다.

준공 단계의 문서 정리와 누락 검토를 짧고 명확하게 시연합니다.

```text
현장 폴더 / ZIP
→ 분석
→ 문서 분류
→ 확보 / 누락 / 확인 필요 / 중복
→ 전체 정리
→ 근거 확인
```

핵심은 파일 하나씩 사람이 열어 판단하지 않아도 되는 경험을 보여주는 것입니다.

---

## Phase 1 — Construction Document AI

Prototype을 실제 현장에서 반복적으로 사용할 수 있는 제품으로 발전시킵니다.

- Windows 현장 폴더
- HWP / HWPX
- PDF / Excel / 이미지 / 도면
- 이메일 첨부파일
- 문서 자동 분류
- 중복·최신본 후보
- 누락 탐지
- 문서 관계 연결
- 제출 준비
- AI 판단 근거 확인

첫 번째 실제 제품 wedge는 준공 문서 업무입니다.

---

## Phase 2 — Document Lifecycle AI

파일의 종류만 분류하지 않고 문서가 **왜 생겼고, 무엇과 연결되며, 현재 어떤 상태인지** 이해하는 단계입니다.

대상 흐름:

- 품질·자재 문서
- 자재승인
- 검측
- 설계변경
- 도면 revision
- 승인·보완·회신
- 준공·사용승인

AIARC는 생성 → 승인 → 변경 → 최신본 → 최종 제출까지 이어지는 문서 생애주기를 연결합니다.

---

## Phase 3 — Project Intelligence

문서뿐 아니라 프로젝트에서 생성되는 정보를 연결해 **프로젝트의 현재 상태를 이해하는 AI**로 발전합니다.

```text
문서
+ 도면
+ 메일
+ 사진
+ BIM
+ 일정
+ 계약·원가
+ 승인·변경 기록
```

이 단계의 핵심 변화는 다음과 같습니다.

> **문서를 관리하는 AI → 프로젝트를 이해하는 AI**

---

## Phase 4 — Architecture / Construction Agent

프로젝트를 이해하는 데서 끝나지 않고 실제 건축·건설 지식업무를 수행하는 방향으로 확장합니다.

장기 대상 업무:

- 법규·대지 검토
- 설계 검토
- 도면 비교·수정
- BIM
- 견적·물량·공정
- 자재·품질·검측
- 설계변경
- 인허가 자료
- 메일·공문·회신
- 준공
- 유지관리 인계

AI가 반복 업무를 수행하고, 사람은 중요한 기술적·법적 판단과 승인에 집중하는 구조를 지향합니다.

---

## Phase 5 — Architecture AI

장기적으로 AIARC는 건축 프로젝트의 목적과 조건을 이해하고 필요한 전문 시스템들과 함께 프로젝트의 지식업무를 수행하는 **건축 특화 AI**를 목표로 합니다.

```text
대지 분석
→ 법규 검토
→ 사업성 검토
→ 기획
→ 설계
→ 도면 / BIM
→ 인허가
→ 견적 / 공정
→ 자재 / 품질
→ 변경관리
→ 준공
→ 유지관리 인계
```

> **AIARC = 건축 프로젝트를 수행하는 AI**

이 내용은 장기 North Star이며 현재 구현된 기능을 의미하지 않습니다.

---

## 왜 문서부터 시작하는가

건축 프로젝트의 실제 상태는 문서, 도면, 이메일, 승인, 변경 기록 등에 흩어져 있습니다.

AI가 건축 업무를 수행하려면 먼저 프로젝트에서 무슨 일이 벌어지고 있는지 이해할 수 있어야 합니다. 준공 문서 업무는 프로젝트 전 과정의 결과물이 모이고 누락·최신본·관계 판단이 집중되는 영역이기 때문에 첫 번째 검증 지점으로 적합합니다.

따라서 AIARC의 전략은 다음 한 문장으로 정리할 수 있습니다.

> **준공서류 프로그램에서 건축 AI로 확장하는 것이 아니라, 건축 특화 AI를 만들기 위해 가장 현실적인 진입점인 준공 문서 업무에서 시작합니다.**

국내 건축·건설의 실제 업무환경을 충분히 깊게 해결한 뒤 더 넓은 시장 확장을 검토합니다.

상세 단계별 구현계획, 평가체계와 내부 R&D 로드맵은 비공개 개발 저장소에서 관리합니다.
