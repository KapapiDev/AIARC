# AIARC Public Roadmap

## 방향

AIARC는 `준공 문서 프로그램이 나중에 건축 전체를 수행하는 AI가 된다`는 로드맵을 사용하지 않습니다.

확장 원리는 하나입니다.

> **준공에서 검증한 문서 생애주기 자동화 구조를, 같은 확인·보완·전달 패턴이 반복되는 인접 workflow로 넓혀갑니다.**

장기 방향은 **Architecture Workflow AI**입니다.

---

## Phase 0 · 0.6.0 Product Demo

현재 단계입니다.

```text
현장 폴더 / ZIP
→ 문서 분석·분류
→ 관계·상태 후보
→ 누락 / 확인 필요 / 중복
→ 전체 정리
→ 원문 근거 확인
```

목표는 준공 문서 정리의 제품 경험을 명확하게 보여주는 것입니다.

---

## Phase 1 · Real Document Validation

실제 또는 익명화된 현장자료로 다음을 검증합니다.

- 문서 유형 분류
- 공종·자재·업무 관계 연결
- 최신 유효본 후보
- 누락·불일치 탐지
- false auto-confirm
- 수작업 시간 감소

0.6.0 Demo와 실제 검증 결과를 구분합니다.

---

## Phase 2 · Document Lifecycle AX

문서를 파일 하나로 보지 않고 lifecycle로 관리합니다.

```text
생성 / 수신
→ 전달
→ 확인
→ 누락·보완
→ 수정본
→ 확인 완료
→ 최신 유효본
→ 최종 제출 반영
```

핵심 기능:

- 문서 관계 연결
- 버전·대체 관계
- 요청·회신·미회신
- 보완 상태
- 역할별 확인 상태
- 최종 패키지 상태

---

## Phase 3 · Project Workspace

여러 참여자가 하나의 프로젝트에 직접 자료를 축적하는 구조를 만듭니다.

```text
프로젝트 생성
→ Project Code
→ 참여자 입장
→ 담당 자료 직접 업로드
→ AI 자동 정리
→ 역할별 확인
→ 보완·수정 누적
→ 최신 유효본 유지
```

이 단계의 핵심 변화는 **전달할 때마다 자료를 다시 정리하는 구조 → 프로젝트에 한 번 축적되고 계속 완성되는 구조**입니다.

---

## Phase 4 · Progressive Closeout

준공 직전에 처음부터 다시 서류를 모으는 작업을 줄입니다.

```text
공사 중 자료 발생
→ 프로젝트에 즉시 축적
→ AI 정리·관계 연결
→ 필요한 확인 수행
→ 보완 상태 추적
→ 유효본 갱신
→ 공사 종료
→ 최종 제출 패키지 생성
```

> **준공서류를 마지막에 정리하는 것이 아니라, 프로젝트가 진행되는 동안 준공 가능한 문서 상태를 계속 만들어갑니다.**

---

## Phase 5 · Adjacent Workflow Expansion

실제 사용자 검증을 통과한 영역부터 확장합니다.

후보:

- 자재·품질
- 감리·검측
- 설계변경 관련 문서
- 인허가 자료
- 준공·사용승인
- 기타 다주체 확인·보완 workflow

문서마다 법적·업무적 절차가 다르므로 하나의 고정 체크리스트를 모든 프로젝트에 적용하지 않습니다.

---

## Phase 6 · Architecture Workflow AI

장기적으로 AIARC는 건축 프로젝트 전반의 문서·정보 workflow를 연결합니다.

```text
Documents
+ Drawings as workflow evidence
+ Email / Attachments
+ Requests / Replies
+ Approvals / Reviews
+ Revisions / Supplements
+ Project roles
        ↓
      AIARC
        ↓
정리 · 연결 · 추적 · 사전확인 · 제출 준비
```

건축 전문가의 설계·법규·기술 판단 자체를 AI가 대체하는 것이 목표가 아닙니다.

> **법적으로 필요한 확인은 사람이 하고, AIARC는 그 확인 사이의 반복적인 문서·정보 업무를 줄입니다.**

---

## 확장 게이트

새 workflow는 다음 조건을 만족할 때만 제품 범위에 넣습니다.

1. 실제로 반복되는 확인·정리·보완 비용이 존재한다.
2. 기존 Project Workspace와 Document Lifecycle 데이터를 재사용할 수 있다.
3. AI가 사람의 책임을 침범하지 않고 검토량을 줄일 수 있다.
4. 실제 고객·사용자 검증에서 반복 사용 가치가 확인된다.

기능 수가 아니라 **반복 업무를 얼마나 실제로 제거했는가**를 기준으로 확장합니다.
