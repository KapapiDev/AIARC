# AIARC Public Roadmap

## 한눈에 보기

```text
준공 문서 자동화
→ AI Project Workspace
→ Project State
→ Project Intelligence
→ Architecture / Construction Agent
→ Architecture AI
```

AIARC는 **준공 문서 자동화**에서 시작하지만, 문서정리 자체가 최종 목적은 아닙니다.

첫 제품에서 검증하려는 핵심은 **AI가 실제 건축 프로젝트 자료의 관계와 상태를 이해할 수 있는가**입니다. 이 능력을 공사 중으로 확장해 프로젝트의 현재 상태와 변화, 미결사항을 계속 이해하는 AI 업무공간으로 발전시키고, 장기적으로 Architecture AI를 지향합니다.

---

## Phase 1. 준공 문서 자동화

현재 0.6.0 프로토타입은 준공 단계에 이미 흩어져 있는 자료를 분석하고, 분류·누락·중복·최신본 후보와 확인할 예외를 보여주는 제품 경험을 시연합니다.

```text
현장 폴더 / ZIP
→ 분석
→ 문서 분류 · 관계 연결
→ 누락 / 중복 / 최신본 후보 / 확인 필요
→ 전체 정리
→ 근거 확인
```

현재 단계의 핵심 질문은 단순합니다.

> **사람이 모든 파일을 처음부터 다시 확인하는 양을 실제로 줄일 수 있는가?**

첫 제품은 회사 전체의 시스템 교체나 여러 외부 참여자의 동시 도입을 전제로 하지 않습니다. 기존 폴더·ZIP·이메일 환경 위에서 사용자 한 명이 먼저 가치를 얻을 수 있어야 합니다.

---

## Phase 2. AI Project Workspace

다음 제품 단계에서는 준공 시점에 한 번 자료를 정리하는 것을 넘어, **프로젝트 자료가 생길 때부터 같은 프로젝트 맥락으로 연결되는 AI 업무공간**으로 확장합니다.

```text
문서 · 도면 · 메일 · 사진 · 변경 기록
                ↓
AIARC가 정리하고 관계를 파악
                ↓
현재 상태와 미결사항을 계속 갱신
                ↓
사용자는 프로젝트에 질문하고 근거를 확인
```

자료가 들어오는 방법 자체보다 중요한 것은, 들어온 뒤 AI가 **무엇이 유효하고 무엇이 달라졌는지 계속 이해하는 것**입니다.

공사 중 자료가 자연스럽게 누적되면 준공 직전에 여러 폴더와 메일을 다시 합치고 정리하는 양도 줄일 수 있습니다.

> **건물을 짓는 동안, 준공서류도 함께 완성됩니다.**

---

## Phase 3. Project State

건축 프로젝트의 실제 상태는 파일 하나에 완성된 형태로 존재하지 않습니다.

예를 들어:

```text
원도면 A
→ 현장 변경지시
→ 수정도면 B
→ 회의록 / 메일
→ 실제 시공 / 현장사진
```

몇 달 뒤에는 다음 질문이 생깁니다.

> **“이 부분 원래 이렇게 되어 있었어?”**  
> **“언제, 왜 바뀐 거야?”**

Project State는 문서, 도면, 메일, 사진과 변경 기록을 연결해 다음을 이해하는 방향입니다.

- 현재 유효한 문서와 도면
- 완료된 것과 미결인 것
- 무엇이 언제 바뀌었는가
- 어떤 근거로 현재 상태가 되었는가
- 누락되거나 충돌하는 정보
- 지금 다음으로 확인해야 할 일

핵심 변화:

> **파일을 찾는 AI → 프로젝트의 현재 상태와 변화 이유를 이해하는 AI**

---

## Phase 4. Project Intelligence

Project State를 바탕으로 단순 조회를 넘어 프로젝트의 위험, 충돌, 누락과 미결사항을 판단하는 단계입니다.

예:

- 지금 이 프로젝트에서 무엇이 진행 중인가
- 어떤 결정이 아직 내려지지 않았는가
- 어떤 변경이 아직 최종 결과에 반영되지 않았는가
- 관련 자료와 근거는 무엇인가
- 사람이 가장 먼저 확인해야 할 것은 무엇인가

AIARC가 지향하는 답변은 단순한 검색결과가 아니라 가능한 경우 **현재 상태 + 변화 흐름 + 원문 근거**를 함께 보여주는 것입니다.

---

## Phase 5. Architecture / Construction Agent

프로젝트 상태를 이해하는 데서 끝나지 않고, 반복 가능한 업무를 실제로 수행하는 방향으로 확장합니다.

```text
현재 프로젝트 상태
↓
다음 업무 판단
↓
필요한 도구 / 전문 Agent 실행
↓
결과와 근거 제시
↓
사람의 승인 또는 예외 확인
↓
프로젝트 상태 갱신
```

법적·기술적 최종 판단과 책임은 사람에게 남기고, 반복 가능하고 검증 가능한 업무부터 자동화합니다.

세부 구현 범위는 실제 제품 검증 결과에 따라 단계적으로 결정합니다.

---

## Phase 6. Architecture AI

장기 North Star는 **Architecture AI**입니다.

건축 프로젝트의 더 넓은 지식업무에는 법규, 설계, 도면, BIM, 견적, 공정, 자재, 품질, 인허가, 문서, 준공 등이 있습니다.

AIARC는 이 모든 것을 한 번에 구현하려 하지 않습니다.

```text
실제 반복업무 해결
↓
프로젝트 자료 이해
↓
Project State
↓
Project Intelligence
↓
전문 업무 실행
↓
Architecture AI
```

> **Architecture AI가 프로젝트를 수행하려면 먼저 프로젝트가 지금 어떤 상태인지 이해해야 합니다. AIARC는 그 상태를 실제 업무에서 먼저 만들고 검증합니다.**

---

## 검증 원칙

큰 비전보다 각 단계의 실제 결과를 우선합니다.

- 현재 구현된 것과 다음 단계의 목표를 구분합니다.
- 실제 사용자와 실제 또는 적법하게 익명화한 프로젝트 자료로 검증합니다.
- AI 판단은 가능한 한 원문 근거와 연결합니다.
- 전문가의 최종 판단과 책임을 자동화됐다고 과장하지 않습니다.
- 새로운 기능은 실제 반복업무를 줄이는지 확인한 뒤 확장합니다.

상세 구현계획, 데이터 모델, 평가체계와 내부 R&D 로드맵은 비공개 개발 저장소에서 관리합니다.
