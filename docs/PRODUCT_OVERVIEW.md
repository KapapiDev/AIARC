# AIARC Product Overview

## 제품 정의

> **AIARC는 건축 프로젝트에서 여러 참여자가 반복하는 문서·정보·업무 흐름을 AI로 자동화합니다.**

현재 제품은 준공 문서 자동화에서 시작합니다. 장기적으로는 자재·품질·감리·설계변경·인허가 등 문서 workflow를 하나의 프로젝트 공간에서 연결하는 **Architecture Workflow AI**를 목표로 합니다.

AIARC는 건축사·감리자·현장소장의 전문 판단 자체를 대체하려는 제품이 아닙니다.

---

## 구조적 문제

건축 프로젝트의 문서는 한 주체에서 끝나지 않습니다. 문서 종류에 따라 실제 순서는 다르지만 자재 제조·유통업체, 건설사, 감리자, 건축주, 허가권자 등 여러 주체 사이에서 자료가 작성·전달·확인·보완·제출됩니다.

일부 감리·건축자재 품질관리·사용승인 업무는 이러한 작성·확인·전달·첨부·제출 구조가 법령으로도 규정되어 있습니다.

필요한 확인은 남아야 합니다. 문제는 그 사이의 반복 업무입니다.

```text
전달
→ 다운로드
→ 다시 분류
→ 누락 확인
→ 보완 요청
→ 수정본 수신
→ 최신본 교체
→ 다시 전달
→ 준공 때 다시 취합
```

AIARC는 이 반복 레이어를 줄입니다.

---

## 제품 구조

```text
프로젝트 생성
→ Project Code 발급
→ 참여자 입장
→ 각자 담당 자료 직접 업로드
→ AI 자동 분류·관계 연결
→ 역할별 확인 항목 제시
→ 보완·수정이 같은 프로젝트에 누적
→ 최신 유효본과 Document State 유지
→ 공사 종료 시 제출 패키지 생성
```

Project Code는 여러 조직이 하나의 프로젝트에 연결되는 UX 원리입니다.

---

## 핵심 차별성

### 1. 프로젝트 코드로 하나의 문서 흐름

각자 관리한 자료를 마지막에 합치는 대신 같은 프로젝트에 직접 축적합니다.

### 2. AI가 문서 생애주기를 계속 관리

- 문서 관계 연결
- 최신 유효본 / 구버전 / 확인 필요
- 누락·미회신
- 요청·보완·수정본·확인 상태
- 최종 제출 반영 여부

### 3. 준공 때 다시 만들지 않음

> **프로젝트가 진행되는 동안 준공 가능한 문서 상태를 계속 만들어갑니다.**

공사 중 누적·확인된 유효 자료에서 최종 제출 세트를 생성합니다.

---

## 현재 제품

AIARC 0.6.0은 준공 단계의 제품 경험을 보여주는 프로토타입입니다.

```text
현장 폴더 / ZIP
→ 분석
→ 분류·관계 연결
→ 확보 / 누락 / 확인 필요 / 중복 / 최신본 후보
→ 전체 정리
→ 원문 근거 확인
```

현재 데모는 샘플 자료와 준비된 AI 결과를 포함합니다. 실제 구현 기능과 Demo 기능을 구분합니다.

---

## 사람과 AI의 역할

AI는 정리·연결·추적과 사전 확인을 담당합니다.

사람은 다음 권한을 유지합니다.

- 법적·기술적 최종 판단
- 감리·건축사 등 법정 확인 책임
- 승인·확인
- 서명·날인
- 예외 판단

불확실한 AI 판단은 자동 확정하지 않고 `확인 필요`로 표시합니다.

---

## 확장 방향

```text
준공 문서 자동화
→ Document Lifecycle AX
→ 자재 / 품질 / 감리 / 설계변경 / 인허가 workflow
→ Multi-party Project Workspace
→ 건축 프로젝트 전반의 Document / Information Workflow AX
→ Architecture Workflow AI
```

`건축 프로젝트 전체를 AI가 수행한다`는 이전 비전은 사용하지 않습니다. AIARC의 확장은 같은 문서·정보 lifecycle이 반복되는 인접 workflow를 자동화하는 방식입니다.
