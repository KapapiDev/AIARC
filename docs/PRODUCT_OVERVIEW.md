# AIARC Product Overview

AIARC는 **준공 단계의 반복적인 문서 정리·누락 확인·보완 업무를 줄이는 Windows 데스크톱 AI**에서 시작합니다.

장기적으로는 건축 프로젝트의 더 넓은 지식업무를 수행하는 **Architecture AI**를 목표로 합니다. 현재의 준공 문서 자동화는 그 목표로 가기 위한 첫 제품입니다.

## 문제

건설 문서는 저장으로 끝나지 않습니다. 공사 중 계속 만들어지고, 검토되고, 수정되고, 보완되고, 최종본으로 확정됩니다.

준공 단계에서는 특히 다음 일이 반복됩니다.

- 전달받은 자료 확인
- 누락 확인
- 보완 요청
- 수정·보완본 수신
- 최신본 반영
- 변경사항의 최종 반영 여부 확인
- 제출 가능한 최종 세트 정리

자료가 잘 정리되어 오는 프로젝트도 있고 그렇지 않은 프로젝트도 있습니다. 문제는 특정 참여자의 정리 수준이 아니라, **여러 단계의 검토 사이에서 같은 자료를 다시 찾고 맞추고 보완하는 일이 반복된다는 것**입니다.

## 현재 제품

현재 0.6.0 프로토타입은 준공 단계에 이미 흩어져 있는 자료를 정리하는 제품 경험을 보여줍니다.

```text
현장 폴더 / ZIP
→ AIARC 분석
→ 문서 분류 · 관계 연결
→ 누락 · 중복 · 최신본 후보 · 확인 필요
→ 전체 정리
→ 예외와 원문 근거 확인
```

핵심 UX는 **자동화가 먼저 일하고, 사용자는 필요한 순간에만 확인하는 것**입니다.

## 왜 준공부터 시작하는가

준공 단계에는 프로젝트 전 과정에서 생성된 결과물이 모입니다. 그래서 문서 종류, 관계, 누락, 최신본, 변경 반영 여부를 한꺼번에 확인해야 합니다.

AIARC는 이 지점에서 먼저 다음 능력을 검증합니다.

- 문서가 무엇인지 이해하는가
- 어떤 업무·자재·공종과 연결되는지 파악하는가
- 최신본과 구버전 후보를 구분할 수 있는가
- 무엇이 빠졌는지 찾을 수 있는가
- 사용자가 처음부터 모든 파일을 다시 확인하는 시간을 줄일 수 있는가

## 차별화된 다음 workflow

AIARC의 다음 단계는 **준공 직전에 하는 정리를 공사 중으로 앞당기는 것**입니다.

```text
프로젝트 생성
→ 프로젝트 코드 / 초대 링크
        ↓
자재 제조·유통업체 · 시공자 · 설계 · 감리 · CM 등
프로젝트에 필요한 역할의 참여자가 자료 추가
        ↓
AIARC 자동 분류 · 관계 연결 · 버전 관리
        ↓
누락 · 보완 · 최신 유효본 · 확인 필요 상태 갱신
        ↓
각 참여자는 자기 업무에서 확인할 항목 중심으로 검토
        ↓
수정본 · 보완 결과 · 확인 결과가 같은 프로젝트에 누적
        ↓
공사 완료
        ↓
누적된 유효 자료에서 준공 · 사용승인용 최종 세트 생성
```

여기서 참여자 구분은 서로 다른 사람을 뜻하지 않습니다. 실제 프로젝트에서는 같은 사람이나 조직이 설계와 감리처럼 둘 이상의 역할을 맡을 수 있습니다.

전문가의 검토와 책임은 그대로 두고, AIARC는 그 전후에서 반복되는 **정리·누락 확인·보완 요청·수정본 반영·전달·추적**을 줄입니다.

> **건물을 짓는 동안, 준공서류도 함께 완성됩니다.**

프로젝트 코드나 공동 저장공간 자체가 차별점은 아닙니다. 핵심은 **자료가 생길 때부터 같은 프로젝트에 연결되고, AI가 문서의 관계·버전·누락·보완 상태를 계속 관리하며, 그 상태를 준공 최종 세트까지 이어주는 구조**입니다.

## AI가 이해해야 하는 것

건축 프로젝트의 현재 상태는 파일 하나만으로 알기 어렵습니다.

문서, 도면, 이메일, 사진, BIM, 승인 기록과 변경본이 서로 다른 곳에 흩어져 있고, 같은 문서도 프로젝트가 진행되는 동안 검토·승인·변경·대체됩니다.

AIARC는 이런 흔적을 연결해 다음을 이해하는 방향으로 발전합니다.

- 현재 유효한 문서와 도면
- 문서와 자재·공종·업무의 관계
- 누락과 미결사항
- 요청과 보완 상태
- 변경 반영 여부
- 다음에 확인하거나 처리해야 할 업무

내부적으로 이 구조를 **Project State Reconstruction → Next-action Execution**이라고 부릅니다.

## 제품 원칙

- **Existing workflow first**: 기존 Windows 폴더·이메일·HWP 중심 환경을 존중
- **Local-first**: 원본과 현장 데이터는 가능한 한 사용자 PC·회사 저장소 중심
- **HWP-aware**: HWP/HWPX를 국내 업무환경의 핵심 형식으로 취급
- **Automation first**: 문제가 없는 문서는 자동 처리하고 예외만 사람에게 표시
- **Evidence before automation**: AI 판단을 가능한 한 원문 근거와 연결
- **Human authority remains**: 법적·기술적 최종 판단과 날인·서명은 사람이 수행

## 현재와 다음을 구분합니다

### 현재 0.6.0

- 준공 문서 자동정리 제품 경험
- 폴더 / ZIP 투입
- 분류·관계·누락·중복·최신본 후보 표시
- 예외와 원문 근거 확인

### 다음 제품 검증

- 프로젝트 코드 / 초대 링크 기반 공동 workflow
- 공사 중 자료 누적
- 문서 상태 지속 관리
- 준공 시 재취합·재정리 감소 검증

현재 프로토타입에 구현되지 않은 기능을 이미 완성된 기능처럼 설명하지 않습니다.

## 장기 방향

```text
준공 문서 자동화
→ Document Lifecycle AI
→ Project State Reconstruction
→ Project Intelligence
→ Architecture / Construction Agent
→ Architecture AI
```

큰 비전은 유지하되, 제품의 가치는 각 단계에서 실제 사용자와 실제 자료로 검증합니다.

상세 구현 방식, 데이터 모델, 문서별 workflow schema, 평가체계와 내부 자동화 로직은 비공개 개발 저장소에서 관리합니다.
