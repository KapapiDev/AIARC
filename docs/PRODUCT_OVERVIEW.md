# AIARC Product Overview

AIARC는 건설회사가 이미 사용하는 Windows 현장 폴더, 이메일, HWP 중심 업무환경 위에서 문서의 흐름을 이해하고 정리하는 local-first 건설 문서 AX 데스크톱 앱입니다.

장기적으로는 건축 프로젝트에 필요한 지식업무 전반을 수행하는 **건축 특화 AI, Architecture AI**를 목표로 합니다. 현재의 준공 문서 자동화는 그 목표로 가기 위한 첫 번째 진입점입니다.

## 문제

건설 문서는 저장으로 끝나지 않습니다. 공사 중 계속 생성되고, 승인되고, 수정되고, 대체되고, 최종본으로 확정됩니다.

현장 실무자는 반복적으로 다음을 확인합니다.

- 이 문서가 어느 현장·자재·공종에 속하는가
- 지금 공사 단계에서 필요한 문서인가
- 어떤 파일이 최신본인가
- 변경사항이 최종 도면과 제출자료에 반영됐는가
- 무엇이 빠졌는가
- 누구에게 무엇을 다시 요청해야 하는가

하지만 더 큰 문제는 **프로젝트의 현재 상태가 한곳에 존재하지 않는다는 것**입니다.

실제 상태는 문서, 도면, 이메일, 사진, BIM, 일정, 승인, 변경 기록과 사람의 기억에 흩어져 있습니다.

## 핵심 아이디어: Project State Reconstruction

AIARC의 핵심 아이디어는 단순히 건축업에 AI를 적용하는 것이 아닙니다.

> **흩어진 프로젝트 산출물과 변경 흔적에서 현재 프로젝트 상태를 재구성하고, 그 상태를 기반으로 다음 업무를 판단하고 실행합니다.**

```text
문서 · 도면 · 메일 · 사진 · BIM · 변경 기록
                    ↓
         Project State Reconstruction
                    ↓
       현재 프로젝트 상태 / 관계 / 미결사항
                    ↓
          Next-action reasoning
                    ↓
             업무 실행
                    ↓
         새로운 결과와 변경 발생
                    ↓
          프로젝트 상태 갱신
```

따라서 장기 제품 정의는 다음과 같습니다.

> **AIARC = 프로젝트의 현재 상태를 재구성하고, 그 상태를 바탕으로 다음 업무를 수행하는 AI**

`Architecture AI`는 AIARC가 향하는 산업적 목적지이고, `Project State Reconstruction → Next-action Execution`은 그 목적지에 접근하는 핵심 제품 아이디어입니다.

## AIARC가 지향하는 경험

```text
현장 폴더 / ZIP / 이메일 첨부
↓
AIARC 분석
↓
문서 분류 · 최신본 후보 · 누락 · 불일치
↓
정상건 자동 처리
↓
예외만 사용자 확인
```

핵심 UX는 **자동화가 먼저 일하고, 사람은 필요한 순간에만 확인하는 것**입니다.

## 첫 번째 진입점

초기 프로토타입은 준공 단계의 문서 정리와 누락 검토에서 시작합니다.

```text
뒤섞인 현장자료
→ 문서 인식·분류
→ 확보 / 누락 / 확인 필요 / 중복
→ 전체 정리
→ 문서 트리 갱신
→ 문제 근거 확인
```

준공 자동정리는 장기 제품의 끝이 아닙니다.

준공 단계는 프로젝트 전 과정에서 생성된 많은 결과물이 한곳에 모이고, 누락·최신본·관계·변경 반영 여부를 함께 판단해야 합니다. 따라서 **Project State Reconstruction을 가장 작고 검증 가능하게 시작할 수 있는 첫 관측 지점**으로 사용합니다.

## 제품 철학

- **Existing workflow first** - 사용자가 이미 쓰는 폴더·메일·HWP 위에서 작동
- **Local-first** - 원본과 현장 데이터는 가능한 한 사용자 PC·회사 저장소 중심
- **HWP-aware** - HWP/HWPX를 국내 업무환경의 핵심으로 취급
- **Automation first** - 정상건은 자동 처리하고 예외만 사람에게 노출
- **Evidence before automation** - AI 판단과 원문 근거를 연결
- **Human authority remains** - 법적·기술적 최종판단과 실제 날인·서명은 사람이 유지

## 장기 방향

```text
준공 문서 자동화
→ Document Lifecycle AI
→ Project State Reconstruction
→ Project Intelligence
→ Architecture / Construction Agent
→ Architecture AI
```

장기적으로는 문서만 관리하는 시스템이 아니라, 프로젝트에서 발생하는 여러 종류의 정보를 관측하고 현재 상태를 재구성한 뒤 다음 업무를 수행하는 시스템으로 확장합니다.

```text
관측
→ 상태 재구성
→ 관계·미결사항 판단
→ 다음 업무 선택
→ 실행
→ 결과 관측
→ 상태 갱신
```

상세 구현 방식, 데이터 모델, 문서별 workflow schema, 평가체계와 내부 자동화 로직은 비공개 개발 저장소에서 관리합니다.
