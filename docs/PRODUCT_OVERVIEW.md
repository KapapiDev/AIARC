# AIARC Product Overview

AIARC의 최종 목표는 건축 프로젝트에 필요한 지식업무 전반을 수행하는 **건축 특화 AI, Architecture AI**입니다.

현재 제품은 그 비전을 한 번에 구현하려 하지 않습니다. 사용자가 이미 쓰고 있는 Windows 현장 폴더, 이메일, HWP 중심 업무환경 위에서 시작해 **문서의 관계와 생애주기를 이해하는 능력**을 첫 번째 검증 영역으로 삼습니다.

## 문제

건설 문서는 저장으로 끝나지 않습니다. 프로젝트가 진행되는 동안 생성되고, 전달되고, 검토되고, 승인되고, 보완되고, 수정되고, 대체되고, 최종본으로 확정됩니다.

실무자는 반복적으로 다음을 확인합니다.

- 이 문서가 어느 현장·자재·공종·업무와 연결되는가
- 어떤 파일이 현재 유효한가
- 무엇이 승인됐고 무엇이 아직 미결인가
- 무엇을 요청했고 회신이 왔는가
- 변경사항이 최종 결과에 반영됐는가
- 무엇이 빠졌고 다음에 무엇을 해야 하는가

더 큰 문제는 **프로젝트의 현재 상태가 한곳에 존재하지 않는다는 것**입니다.

실제 상태는 문서, 도면, 이메일, 사진, BIM, 일정, 승인, 변경 기록과 사람의 기억에 흩어져 있습니다.

## 최종 비전: Architecture AI

AIARC는 장기적으로 프로젝트의 흩어진 정보를 연결해 현재 상태를 이해하고, 그 상태를 바탕으로 다음 업무를 판단·수행하는 Architecture AI를 목표로 합니다.

```text
문서 · 도면 · 메일 · 사진 · BIM · 변경 기록
                    ↓
         Project State Reconstruction
                    ↓
       현재 프로젝트 상태 / 관계 / 미결사항
                    ↓
          Next-action reasoning
                    ↓
             업무 실행
                    ↓
          프로젝트 상태 갱신
```

> **AIARC = 프로젝트의 현재 상태를 진단·재구성하고, 그 상태를 바탕으로 다음 업무를 수행하는 AI**

`Architecture AI`는 AIARC가 향하는 최종 제품 범위이고, `Project State Reconstruction → Next-action Execution`은 그 목적지에 접근하는 핵심 제품 아이디어입니다.

## 첫 번째 검증 영역: 문서 생애주기

현재 제품에서 먼저 검증하는 차별성은 세 가지입니다.

### 1. 문서 관계 연결

HWP, PDF, Excel, 사진, 메일 첨부를 자재·품질·감리·공사·준공 등 관련 업무와 연결합니다.

### 2. 최신 유효본 판별

단순 수정일이 아니라 문서 내용, 버전, 승인·보완·회신 이력을 함께 보고 `유효본 / 구버전 / 확인 필요`를 구분합니다.

### 3. 요청·보완·승인 상태 추적

`요청 → 회신 → 첨부 → 보완 → 수정본 → 승인` 흐름을 연결해 `확보 / 미회신 / 보완 중 / 확인 필요` 상태를 추적합니다.

문서 생애주기를 이해하는 이유는 문서정리를 잘하기 위해서가 아니라, **문서를 통해 프로젝트의 현재 상태를 이해하기 위해서**입니다.

## 현재 vertical slice: 준공 문서 자동화

첫 프로토타입은 준공 단계의 문서 수집·정리·누락 검토에서 시작합니다.

```text
뒤섞인 현장자료
→ 문서 인식·분류
→ 관계 연결
→ 확보 / 누락 / 확인 필요 / 중복 / 최신본 후보
→ 전체 정리
→ 문서 트리 갱신
→ 문제 근거 확인
```

준공 단계는 프로젝트 전 과정에서 생성된 많은 결과물이 한곳에 모이고, 누락·최신본·관계·변경 반영 여부를 함께 판단해야 합니다. 따라서 **Project State Reconstruction을 가장 작고 검증 가능하게 시작할 수 있는 첫 관측 지점**으로 사용합니다.

## 제품 경험

```text
현장 폴더 / ZIP / 이메일 첨부
↓
AIARC 분석
↓
문서 분류 · 최신본 후보 · 누락 · 불일치
↓
정상건 자동 처리
↓
예외만 사용자 확인
```

핵심 UX는 **자동화가 먼저 일하고, 사람은 필요한 순간에만 확인하는 것**입니다.

## 제품 철학

- **Existing workflow first** - 사용자가 이미 쓰는 폴더·메일·HWP 위에서 작동
- **Local-first** - 원본과 현장 데이터는 가능한 한 사용자 PC·회사 저장소 중심
- **HWP-aware** - HWP/HWPX를 국내 업무환경의 핵심으로 취급
- **Automation first** - 정상건은 자동 처리하고 예외만 사람에게 노출
- **Evidence before automation** - AI 판단과 원문 근거를 연결
- **Human authority remains** - 법적·기술적 최종판단과 실제 날인·서명은 사람이 유지

## 장기 방향

```text
준공 문서 자동화
→ Document Lifecycle AI
→ Project State Reconstruction
→ Project Intelligence
→ Architecture / Construction Agent
→ Architecture AI
```

AIARC는 큰 비전을 나중에 붙이는 방식으로 확장하지 않습니다. **처음부터 Architecture AI를 최종 비전으로 두고, 현재 제품에서 가장 작고 검증 가능한 능력부터 증명합니다.**

상세 구현 방식, 데이터 모델, 문서별 workflow schema, 평가체계와 내부 자동화 로직은 비공개 개발 저장소에서 관리합니다.
