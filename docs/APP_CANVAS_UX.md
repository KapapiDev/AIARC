# AIARC 중앙 작업 캔버스 UX

Updated: 2026-09-08
Status: Current design baseline
Related: `docs/APP_DESIGN.md`

## 0. 목적

이 문서는 AIARC 데스크톱 앱의 중앙 작업영역에서 **문서 뷰어와 AI 대화를 별도 패널로 분리하지 않고 하나의 연속된 작업공간으로 결합하는 UX**를 정본으로 기록한다.

핵심 원칙:

> **중앙은 뷰어와 채팅이 나뉜 두 칸이 아니라, 문서와 AI가 함께 존재하는 하나의 Workspace Canvas다.**

AIARC는 범용 채팅앱도, 전통적인 문서관리 프로그램도 아니다. 사용자는 문서를 일일이 읽고 명령하는 대신 AIARC가 먼저 처리하고, 필요할 때 문서 근거를 확인하거나 자연어로 추가 지시한다.

---

## 1. 중앙 작업영역의 기본 개념

중앙에는 고정된 `Viewer pane`과 `Chat pane`을 상하로 분리하지 않는다.

대신 하나의 중앙 캔버스가 현재 상황에 따라 자연스럽게 변한다.

### 문서가 없을 때

대화가 중앙 공간 전체를 사용한다.

```text
┌──────────────────────────────────────────────┐
│                                              │
│                    AIARC                     │
│                                              │
│        오늘 어떤 현장 업무를 처리할까요?     │
│                                              │
│  이전 대화                                   │
│  이전 대화                                   │
│  이전 대화                                   │
│                                              │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ 파일·폴더를 드롭하거나 지시하세요     │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

대화는 일반적인 LLM 데스크톱 앱처럼 아래에서 위로 계속 쌓일 수 있다.

### 문서가 열려 있을 때

문서가 중앙 캔버스의 주 콘텐츠가 된다.

대화는 별도의 독립 패널로 화면을 잘라내는 대신 **문서 위에 자연스럽게 존재하는 오버레이 레이어**가 된다.

```text
┌──────────────────────────────────────────────┐
│                                              │
│                 DOCUMENT                     │
│                   VIEW                       │
│                                              │
│                                              │
│              문서 내용 / 페이지              │
│                                              │
│                                              │
│                 ░░░░░░░░                     │
│              대화 fade 영역                  │
│                                              │
│  AIARC: 정리가 완료되었습니다.               │
│  누락 가능 문서 3건을 찾았습니다.            │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ AIARC에게 지시하거나 파일을 드롭하세요 │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

문서를 보기 위해 채팅 모드에서 뷰어 모드로 전환되는 느낌이 없어야 한다.

**같은 AIARC 작업공간에서 AI가 현재 보고 있는 문서가 자연스럽게 나타나는 느낌**을 목표로 한다.

## 2. 문서와 대화의 시각적 결합

### 2.1 Gradient fade

문서가 열려 있는 상태에서는 대화가 위쪽으로 올라갈수록 점차 흐려져 문서를 가리지 않게 한다.

개념 예:

```text
하단 최근 대화     100%
                   90%
                   70%
                   40%
상단 오래된 대화    0%
```

실제 구현은 단순 opacity 변경보다 CSS mask / gradient / backdrop 처리 등 가장 자연스러운 방식을 검토한다.

목표는 효과 자체를 과시하는 것이 아니다.

- 최근 AI 결과와 현재 명령은 읽기 쉬워야 한다.
- 오래된 대화는 문서 시야를 침범하지 않아야 한다.
- 문서와 대화가 서로 다른 프로그램처럼 느껴지지 않아야 한다.

### 2.2 문서가 없으면 fade를 적용하지 않는다

현재 문서가 없을 때는 대화가 중앙 작업공간 전체를 차지하므로 위로 계속 스크롤되는 일반적인 대화 UX를 사용한다.

즉 동일한 대화 인터페이스가 컨텍스트에 따라 자연스럽게 두 상태를 가진다.

```text
No document
→ Full conversation canvas

Document open
→ Document-first canvas + conversation overlay
```

## 3. 영역은 사용자가 조절할 수 있어야 한다

AIARC의 주요 영역은 고정 비율로 잠그지 않는다.

### 3.1 좌측 사이드바

좌측 현장/문서 트리의 폭을 사용자가 드래그하여 조절할 수 있게 한다.

- 최소 폭 제한
- 최대 폭 제한
- 마지막 사용 폭 기억

문서명이 길거나 깊은 트리를 볼 때는 넓힐 수 있고, 문서 자체에 집중할 때는 줄일 수 있어야 한다.

### 3.2 대화 노출 높이

문서가 열려 있을 때 사용자는 AI 대화의 노출 높이를 직접 조절할 수 있다.

예:

```text
문서 중심
Viewer 85% / Conversation 15%

기본
Viewer 70% / Conversation 30%

대화 중심
Viewer 40% / Conversation 60%
```

단, 이것을 전통적인 split pane처럼 두 개의 딱딱한 창으로 보이게 만들지 않는다.

**조절되는 것은 대화 레이어의 존재감이지, 중앙 작업공간 자체가 둘로 분리되는 것이 아니다.**

### 3.3 빠른 상태 전환

향후 다음과 같은 조작을 검토할 수 있다.

- 대화 최소화: composer + 최근 상태만 표시
- 대화 확장: 긴 대화·분석을 위해 위로 확장
- 문서 집중: 대화 대부분 숨김
- 대화 집중: 문서의 시각적 존재감을 줄이고 대화 확대

최종 인터랙션은 프로토타입 시각 검증 후 확정한다.

## 4. 대화와 문서는 서로 연결되어야 한다

대화 오버레이는 단순히 문서 위에 떠 있는 채팅창이 아니다.

AI의 결과와 뷰어가 양방향으로 연결되어야 한다.

예:

```text
AIARC:
시험성적서 제품명이 자재승인원과 일치하지 않습니다.

자재승인원: ABC-100
시험성적서: ABC-120

[근거 보기]
```

`근거 보기` 또는 해당 문장을 클릭하면:

```text
→ 뷰어가 관련 시험성적서 페이지로 이동
→ ABC-120 위치 하이라이트
→ 필요 시 관련 자재승인원과 비교
```

반대로 사용자가 뷰어에서 특정 문서나 영역을 선택하고 질문하면 AI 대화가 현재 선택 컨텍스트를 자동으로 이해해야 한다.

```text
사용자: 이 부분 문제 없어?
```

사용자가 파일명이나 페이지를 다시 설명하지 않아도 현재 뷰어 컨텍스트를 기준으로 처리하는 것이 목표다.

## 5. 전체 앱과의 결합

전체 기본 셸은 기존 `APP_DESIGN.md`의 한 UI 원칙을 유지한다.

```text
┌───────────────┬──────────────────────────────────────────────┐
│ AIARC         │                                              │
│               │                                              │
│ 현장          │            CENTRAL WORKSPACE                 │
│ ▾ OOO 현장    │                                              │
│               │       Document + AI Conversation             │
│ 문서          │          Unified Canvas                      │
│ ├ 자재        │                                              │
│ ├ 품질        │                                              │
│ ├ 감리        │                                              │
│ ├ 공사        │                                              │
│ └ 준공        │                                              │
│               │                                              │
│ 확인 필요   3 │                                              │
│ 누락        5 │                                              │
│               │                                              │
├───────────────┤                                              │
│ 신규 메일 2건│                                              │
│ 가져오기      │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

좌측은 현장과 문서 구조를 지속적으로 유지하고, 중앙만 사용자의 현재 업무 컨텍스트에 따라 유동적으로 변화한다.

## 6. UX 의도

이 구조가 해결하려는 문제는 다음과 같다.

### 기존 split UI의 문제

```text
Viewer
────────────
Chat
```

이 구조는 구현하기 쉽지만 다음 위험이 있다.

- 문서와 AI가 별개의 도구처럼 느껴진다.
- 작은 노트북 화면에서 둘 다 좁아진다.
- Chat 영역이 항상 공간을 소비한다.
- 문서를 보지 않을 때도 빈 Viewer 공간이 남을 수 있다.
- AIARC가 전통적인 DMS + 챗봇처럼 보일 수 있다.

### Unified Canvas의 목표

```text
문서가 없을 때  → AI conversation workspace
문서가 있을 때  → AI-assisted document workspace
```

앱의 중심을 바꾸지 않고 컨텍스트만 바뀐다.

이를 통해 AIARC는 **대화앱에 문서뷰어를 붙인 제품**도 아니고 **문서뷰어에 챗봇을 붙인 제품**도 아닌 하나의 AI 작업환경으로 보이게 한다.

## 7. AX 원칙과의 관계

이 UI는 사용자가 AI와 오래 대화하게 만들기 위한 것이 아니다.

AIARC의 최상위 UX는 계속 다음과 같다.

```text
자료를 던진다
→ AIARC가 알아서 분석한다
→ AIARC가 알아서 정리안을 만든다
→ 사용자는 필요한 경우 딸깍한다
→ 완료
```

대화는 다음 경우에만 자연스럽게 등장한다.

- AI가 수행한 작업의 요약
- 예외 또는 확인 필요 사항
- 사용자 승인
- 추가 지시
- AI 판단 근거 확인
- 문서에 대한 자유 질문

즉 **Conversation is an interface, not the workflow.**

---

## 8. 구현 시 금지사항

다음 방식으로 퇴행하지 않는다.

1. 뷰어와 대화를 고정된 상하 70:30 패널로 분할
2. 문서가 없는데 빈 뷰어 영역 유지
3. 문서가 열릴 때 별도의 `Viewer mode`로 화면 전체 전환
4. AI 대화를 상시 큰 패널로 고정
5. 문서를 보기 위해 대화를 닫아야 하는 구조
6. 대화를 보기 위해 문서를 완전히 닫아야 하는 구조
7. 본사/현장 사용자별로 이 UX를 따로 설계

프로토타입 구현에서 기술적으로 완전한 오버레이가 어렵다면 단순한 근사 구현은 허용하지만, 최종 지향점은 반드시 **Unified Workspace Canvas**로 유지한다.

---

## 9. 아직 확정하지 않은 세부 구현

다음은 방향만 확정되었고 구체 방식은 프로토타입에서 검증한다.

- fade 시작 위치와 강도
- 대화 레이어의 기본 높이
- drag handle의 시각적 표현
- 대화 확장/축소 애니메이션
- 문서와 대화 사이 backdrop 처리
- 문서 스크롤과 대화 스크롤의 충돌 방지
- 작은 화면에서의 responsive behavior
- 대화가 길어질 때 과거 메시지 접근 방법
- 여러 문서를 비교할 때 캔버스 동작

디자인 구현자는 임의로 고정 split pane을 확정하지 말고 이 UX 의도를 유지한 상태에서 시각적·기술적 대안을 검증해야 한다.

---

## 10. 한 줄 정본

> **AIARC의 중앙은 하나의 작업 캔버스다. 문서가 없으면 대화가 공간을 쓰고, 문서가 열리면 문서가 중심이 되며 대화는 그 위에 자연스럽게 겹친다. 사용자는 각 영역의 존재감을 필요에 따라 조절할 수 있다.**
